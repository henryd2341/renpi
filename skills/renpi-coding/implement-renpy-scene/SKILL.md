# 整合完整 RPY

进入条件：本轮入口/出口明确，所需专业产物已经交回且写入责任转给 Coding。读取 [Coding 边界](../references/coding-contract.md)，需要的语法按 [SDK 查询](../consult-renpy-sdk/SKILL.md) 核对。

## 1. 先打通正文与调用链

- 比较 Writing 实际正文与原文/细纲、允许改动范围；保留顺序、说话者、玩家权限和停止点。剧情问题交 Writing；技术转义保留屏幕实际语义。
- 核对引号、反斜杠、`[` 插值与 `{` 文本标签。区分字面字符和有意标签/插值，按 SDK `text.html` 处理；从基础 RPY 再包入文本常量时避免二次转义。中文长句的分页也是可见文本结构调整，既有单元还要评估执行语句身份。
- 特别核对常量内部原有插值：普通 `[正文常量]` 不自动递归展开其中的变量；`!i`、`!t`、`!q` 分别涉及递归插值、翻译、标签引用，按原文意图与既有模板选用，不统一批量套旗标。玩家输入作为数据呈现，避免把其中的表达式或标签当脚本执行。
- 合并 Character 定义，复用已确认标识；检查所有被加载脚本的 label、image、transform、screen、store 变量及通道冲突。新增符号沿项目命名习惯分配稳定前缀，重命名时同时检查调用方、翻译和已有存档影响。
- 接入真实入口和出口：可返回单元由既有调用方 `call`，结束 `return`；`jump` 是转移，不自动带返回点。长期调用点复用稳定 `from` 标识。避免落入相邻 label；空调用栈的 return 回主菜单，不当作“等待下一轮”。
- 正文修订沿用 [正文/执行结构分离](../references/coding-contract.md#正文修订与兼容)。角色/常量用合适的 `define`；会变化的剧情状态用 `default`，不把 init-time 容器当存档变量。

## 2. 把演出安排到具体节拍

先按 [演出基线与节拍表](../references/presentation-recipes.md#演出基线与适用范围) 确认本轮适用项与已选例外，将默认行为接到真实共享定义，再在正文变化节拍引用。完成条件是实际 RPY/配置已有调用，单写演出建议仍是草稿。

- 多角色同屏：按 [说话者聚焦](../references/presentation-recipes.md#说话者聚焦) 接通 Character/tag、在场映射、明暗更新和恢复；保留现有回调，明确旁白/画外音/群体发言表现。
- 人物进退场与换表情：按 [ATL 与转场](../references/presentation-recipes.md#atl-与转场) 分开站位、焦点和一次性动画，避免换脸重播入场；有意硬切按既定节拍保留。
- 文本：按 [文字渐显](../references/presentation-recipes.md#文字渐显与阅读节奏) 核对有效偏好、样式和 say screen，落实原生渐显及调节入口，维护玩家设置与稳定正文映射。

- 图像：背景/CG/立绘/局部补图的用途分开，明确层、tag、表情、尺寸、裁切与站位；透明边缘、脚底基线、文字框遮挡按实际画幅核对。
- 音频：按音乐使用表安排通道、循环、音量、淡入淡出、续播与停播；音效、环境音、语音各有适当生命周期。
- 动画：优先少量可复用 transform，区分静态站位、入退场、持续动画和转场；镜头移动不掩盖当前文字/选项，自动播放、跳过和回退仍有确定终态。
- 屏幕：复用确认的 GUI；短交互、持续 HUD 和故事选择分别接入正确调用方式。screen 求值/预测保持纯展示，外部制作与接入通过既有显式操作处理。

基础调用形式可参考 [场景样例](assets/scene-example.rpy)。它展示定义、稳定正文插值、场景/表情、音乐/音效、位置 screen 和完整退出；双人焦点及文字偏好按本轮工程另行落实。先按配方中的资产映射适配，样例图片/声音名称不是项目现有素材。不要把样例角色、剧情、分辨率假设或新的 start 标签塞进既有游戏。

## 3. 补齐交互与资源闭环

只有用户或剧情方案已明确的选择才落入 `menu`/交互；Coding 不为了展示引擎能力制造选项。普通局部交互可用 Ren’Py 返回值处理；Ren’Pi 选择点的身份、分支绑定、制作触发复用项目已有桥接入口，按钮绘制本身不触发制作。

变量保存范围、screen 返回后的控制流、重复进入、背景/立绘残留、跨单元音乐延续、临时通道/屏幕清理逐项明确。仅清理本单元拥有的资源；全局 HUD 或约定连续 BGM 保持。媒体暂缺时保留工程草稿和缺口，正式候选的必需引用全部落到真实交付。

## 4. 留下可复用的启动脚本

启动脚本是 Coding 的必需交付，不等用户另行索要。首个可运行工程在项目根目录留下实际脚本，而非只在回复中给出命令；后续单元复用已有入口，仅在启动条件变化或入口缺失时修补。

- 沿用项目命名和当前平台：Windows 可用 `start-game.cmd` 或 `start-game.ps1`，其他平台采用对应脚本；已有可用脚本就复用，不为每个单元另建一份。
- 从脚本所在目录定位含 `game/` 的项目根目录，正确引用含空格、中文的路径，不依赖调用者当前目录。SDK 沿用已确认配置或 `RENPY_HOME`；校验必需路径，缺失时显示具体配置方法并以非零码退出，不把本机 SDK 绝对路径固化成通用模板。
- 默认只启动现有游戏。确需 Pi/GUI 桥接时复用项目真实启动流程并说明涉及的进程；测试 fixture 入口不充当正式入口。启动不附带模型/依赖下载、素材制作、额外 compile/lint、存档清空或全局配置改动；引擎正常加载产生的缓存另按项目约定处理。
- 保留启动错误与退出结果，交代日志位置；双击入口报错时让用户有机会读到诊断。交接给出脚本路径、准确运行方法及 SDK 前提；`.ps1` 给出 PowerShell 调用方式，不把默认双击当作执行方式。

通过交付脚本完成 [运行验证](../verify-renpy-candidate/SKILL.md#2-只运行受影响场景)，脚本存在不等于启动成功。
