# 确定本轮工作

读取 [Coding 边界](../references/coding-contract.md)。先读取本轮实际涉及的文件与调用方，而非把所有历史原型或全篇资料塞入上下文。

## 从既有成果出发

1. 读取程序给出的任务/分支/位置/状态及最新用户要求。辨别开场、续作、直接修改、演出补充或显式重新生成；已在执行的任务核对后继续，避免重复派发。
2. 读取 init 交接、有效前情、源文索引/本轮范围、正文记忆；补充资料只在适用范围内覆盖旧依据。读取上一单元尾段与本轮接续点。
3. 扫描当前脚本及调用方：入口 label、调用/返回、角色标识、image tag/属性、transform、screen、变量、通道及公共定义。所有加载的 RPY 共用符号空间，分支文件夹不构成命名空间。
4. 读取已选 GUI/视觉基准、音乐使用表、立绘差分/站位和 Image 交付；检查真实文件、尺寸/透明、字体、音频用途与可复用条件。候选目录中的最新文件不等于被选素材。
   涉及开场/新场景、多角色对话或表现修订时，对照 [演出基线](../references/presentation-recipes.md#演出基线与适用范围) 盘点说话焦点、入退场和文字渐显：现有实现、有效偏好、已确认例外及本轮缺口。将共享实现的调用方纳入影响范围，局部任务保留未涉及项。
5. 核对当前可用工具、已启用角色及 SDK 位置/版本。继承 init 环境结果，只复查本轮依赖和发生变化的项；使用 [SDK 查询](../consult-renpy-sdk/SKILL.md) 解决具体语义问题。

## 输出一份最小整合清单

复用已有任务交接格式；没有时在分配的创作目录建立 `coding-unit.md`。它只承载工程计划/引用，任务状态仍由程序管理。

| 项目 | 必须明确的信息 |
| --- | --- |
| 单元与依据 | 当前目标引用、原文范围/细纲、已采用前情、用户允许的改动、停止点 |
| 调用约定 | 入口/参数、由谁 call 或 jump、返回值/返回位置、已有交互入口 |
| 文件与符号 | 本轮产物、共享/分支归属、修改责任人、复用/新增/冲突符号 |
| 正文 | 已有基础 RPY、需要 Writing 的范围、角色定义和文本映射 |
| 演出 | 采用基线/例外、共用实现位置、正文节拍对应的在场人物/焦点/表情/进退场/文本音频节奏及退出恢复状态；按配方填最小节拍表 |
| 缺口 | 完整已知清单，区分本轮必需、已有可复用、可延后；对应责任和依赖 |
| 验证 | 编译/lint/引用/入口、按影响选取的动态验收场景与预期结果、旧档/回退、Review 是否启用 |

给 Writing 的模板应有真实入口约定与可用角色；给 Image 的请求有已明确的一刻与用途。尚待确定的事实直接列为缺口，不伪造路径、入口或素材已存在。

## 决策与停止点

保持已有用户决定；无影响的小技术选择按教程与项目习惯完成。仅在剧情授权、视觉方向、玩家控制、破坏性替换或兼容恢复入口确实需要决定时提问，并带上已知清单、影响及建议，不让用户重复回答已确定事项。

音频没有用途就先明确触发与持续范围；缺透明立绘先进入既有 [立绘准备](../../renpi-initialization/prepare-character-sprites/SKILL.md)；GUI 尚缺基准按 [GUI 设计](../../renpi-initialization/design-game-gui/SKILL.md) 承接。素材依赖可提前委派，整合完成依赖必须满足。输出足以分配具体文件后进入 [委派](../delegate-production/SKILL.md)，不把清单扩展成第二套产品规划。
