# Coding 的职责与边界

有效依据：[Agent 分工](../../../docs/wayfinder/tickets/RP-006.md#resolution-comment--2026-09-19)、[项目布局](../../../docs/wayfinder/tickets/RP-009.md)、[领域约定](../../../CONTEXT.md)。本组是制作技能源码，不新增调度器、业务 API 或安装配置，也不把历史原型当作已完成产品。

开始或恢复工作先按 [工作区读取与约束](../../renpi-initialization/references/project-contract.md#工作区读取与约束) 核对真实目录、项目规则、交接及执行范围；新会话沿用已确认约束，任务与候选身份仍由程序核对。

## 任务与文件归属

- 程序提供任务、目标分支、阅读位置、内容依据及控制状态；Coding 核对后使用。GUI 当前浏览位置与在途任务分开，导航不重绑任务。
- 当前有效剧情取目标分支实际 flow 及适用源信息。全局资料是设定依据，不全是已发生剧情；其他分支、未选后果、取消草稿只有明确引用时作为参考。
- 创作源与运行投影分开。沿用实际项目 `authoring/shared/`、`authoring/branches/<已有标识>/`、交付/候选路径；源材料保留原件。`game/`、HEAD、绑定和管理状态由现有程序操作维护。
- 同一文件同一时刻只有一个写入者。子任务交付并释放后 Coding 才接手，返修重新交接；已有同名文件不代表覆盖许可。
- Markdown 只记录工程依据、产物引用与待办，不成为第二份任务状态数据库。身份、候选版本、文件范围、取消/补充状态以程序核对为准。

## 角色分工

| 角色 | 负责 | 交回 Coding 的内容 |
| --- | --- | --- |
| Writing | 源文/设定阅读、剧情、基础 RPY、值得保留的文本信息 | 独立正文、新角色定义、来源/细纲、正文记忆及整合说明 |
| Image | 场景插图、CG、补充图、init 提前补图 | 实际素材、用途/差分推荐、技术和视觉检查、制作来源 |
| Coding | 委派、技术整理、符号整合、图像音频、ATL/界面/流程、验证和请求接入 | 完整候选与当前版本证据、真实接入结果及下轮交接 |
| Review（启用时） | 独立读取候选及验证证据 | 通过/需修改/受阻报告，问题定位与依据；产物保持只读 |

专业角色只向 Coding 提出协作需求。Coding 可分轮调用同一角色，或安排写入范围互斥的并行任务；不把长材料拆成无边界的递归代理树。未启用 Writing 时 Coding 可兼任创作，仍走其源文、文风及玩家控制约束。Review 未启用不等于 Coding 验证已通过；必要检查仍受用户确认的执行范围约束。

转义、分页、定义合并、调用和演出调整属于 Coding；补事件、改变因果、代替玩家发言/行动/想法、改角色声音属于剧情修改，按已确认范围交 Writing。图像演出也应尊重当前视角：隐藏人物、物品和未来 CG 会泄露正文未公开的信息。

## 正文修订与兼容

沿用 [Q85 已确认策略](../../../docs/wayfinder/tickets/RP-011.md#q85-confirmed)：由 Coding 将可修改正文与稳定执行语句分离；Writing 仍交基础 RPY。

- 复用项目已采用的 init-time 文本常量、固定插值执行语句与稳定映射。正文常量、角色定义和执行语句各自归位；新增句子分配新映射，保持旧映射，不以新行号批量重编号。
- 修订构建携带**同路径上一已接入 RPYC**供 SDK 沿用未变语句身份，再以新源码编译。候选、自测或旧失败构建的 RPYC 不冒充该依据；保留历史源码和原编译产物。
- 这是受约束的正文修改策略，翻译 id 或文件路径单独不构成兼容证明。插删、重排、说话者/调用链/流程改变、文本分页引入新 say 都要重新判断兼容；多句多角色不自动继承早期小样本结论。
- 旧存档、回退与当前选项绑定分别验证。落点失效时保留存档及诊断，由用户选择已知有效恢复入口；不猜位置、不静默回到分支开头。
- 编译/lint 构建与回退/旧档验证使用隔离副本。证据冻结后再编译可能改动 RPYC；变更即重建受影响证据，不向用户报告旧哈希已证明新文件。

## 生命周期与停止

任务取消、补充、继续制作和重新生成通过现有控制入口处理，普通排队消息不冒充控制命令。停止先登记取消，再通知工作停止；结果不明先核对原作业。原写入者仍活跃时保留其文件所有权；晚到结果留作待处理，不自动接入。

自动技术修复沿用同一单元，默认最多两轮，重新委派不重置额度。额度用尽保留产物和诊断；用户明确继续时开启新的有界批次。手动重新生成的分支规则由程序处理，区别于技术返修。

必要工具、角色或接入能力缺失时，完成仍可独立完成的创作成果，准确记录所缺入口与依赖；运行、Review 或接入门槛保留原状态。技能不模拟成功回执或手填业务状态。
