# 委派与交付模板

这些是给专业角色的内容模板，不是新业务协议字段。按宿主既有工具编码传递，身份和版本引用由程序核对。

## 每次委派

```text
目标：本轮要完成的具体成果；角色为 Writing / Image / Review。
任务依据：程序给出的任务、分支、位置与版本引用。
内容依据：适用源文件及范围、有效前情、用户本轮要求、已确认决定。
参考：仅所需的视觉/风格/符号/技术说明；标明参考与已发生事实的区别。
输入文件：绝对路径及关键位置；已有产物优先复用。
输出文件：明确允许修改的文件或独占目录；其余产品文件保持只读。
调用约定：下述角色专属信息。
验收：可观察的完成条件，以及仍需 Coding 检查的内容。
停止点：本轮边界、修复剩余额度、缺依赖时交回什么。
交付：目标引用、状态、实际文件清单、检查证据、问题/协作需求。
协作：不独占代码库，保留他人改动；仅 Coding 重新分配文件和跨角色工作。
```

## 角色专属信息

**Writing**：原文/自由创作/混合的明确范围；本轮玩家输入及台词/动作/想法权限；入口 label 与 call/return 或既有接续约定；可用 Character 标识；独立基础 RPY 位置；新增角色定义单独列明。Coding 保留已确认正文修改约束和技术整合责任。已有原文跳过通用大纲与文风流程。

**Image**：场景/CG/补充图/立绘/基准候选用途；精确画面时刻；可见人物与状态；视觉基准及各参考图角色；长宽比、透明、构图安全区、文字框/站位限制；共享/分支归属；已有素材/作业身份。后端×模型×工作流由 Image 按实际可用能力确认。验收需要真实图片及交付记录，而非提示词占位。

**Review**：冻结候选及对应证据；适用契约与有意保留限制；只读范围、报告路径、判定规则。按 [Review 入口](../../renpi-review/review-renpy-candidate/SKILL.md) 审查，并沿用宿主实际格式或其报告内容模板。可执行分配的验证，但其构建输出必须在隔离检查区，避免修改被冻结候选。缺少必要运行证据与已发生运行失败分别记录。

## 收回记录

```text
目标/候选引用：实际程序记录。
状态：完成 / 受阻 / 失败（完成只表示本角色分配成果完成）。
产物：逐项文件、用途、依据和归属；明确待 Coding 接入项。
验证：实际执行项、工具结果/证据路径；未执行项及原因。
变化：新增定义、选用图、正文范围或审查问题等角色专属信息。
交接：写入是否结束；下一责任人；具体待办/协作需求。
```

Coding 读取文件后才能接受交付。文稿的下一轮文本信息交 [文本记忆](../../renpi-writing-plots/remember-story-text/SKILL.md)；通道、路径、构建命令、图像参数、工程故障归 Coding/素材交付，不混入故事记忆。
