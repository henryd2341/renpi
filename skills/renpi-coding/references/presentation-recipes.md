# 演出基线与图片、音频、ATL、界面配方

这是整合决策表，不是语法全集。具体参数查询 [SDK 主题索引](sdk-topic-map.md)。只采用本轮需要的演出，维持用户已确认基准。

## 演出基线与适用范围

目标是让读者辨认发言者、感知场面变化并顺畅阅读，而非让所有元素持续运动。新单元或本轮涉及的表现项，在没有已确认相反风格时采用下列基线；既有刻意硬切、即时显示、等亮群像或减少动态的选择优先，记录其适用范围。纯正文、纯音频等局部任务只处理实际受影响项，未触及的历史单元保留原状。

| 项目 | 默认结果 | 适用条件与例外 |
| --- | --- | --- |
| 说话焦点 | 当前发言者正常色，其他在场人物轻微压暗，切换短渐变 | 多人立绘同屏；旁白、画外音和群体发言按下节处理；单人场景保持自然亮度 |
| 进退场 | 普通出现/离开短淡入淡出；明确走入/让位才加缓动位移 | 保留剧情刻意硬切；表情替换保持站位，独立于入场 |
| 文字渐显 | 使用原生文字速度，保留点击补全文、速度调节和即时显示 | 沿用玩家偏好；特殊字幕、通知和既定即时文本按用途区分 |

呼吸、眨眼、弹跳、镜头推拉、粒子、Live2D 与逐字音效均为按剧情/需求选用的增强项。先完成基础可读性；需要额外素材时登记缺口，仅凭“增加动感”不触发整套素材重做。

### 共用实现与节拍表

先查项目已有 Character、transform、say screen 和配置；焦点、入退场、文字偏好沿用或补在项目现有共享定义中。剧情文件引用公共符号，避免每个分支生成一套回调。修改共享定义时列出实际调用方及跨单元影响，沿用 [兼容边界](coding-contract.md#正文修订与兼容)。

在已有 `coding-unit.md` 中记录采用基线、例外和最小节拍表，不新增第二份状态文件：

| 正文定位/事件 | 在场角色与 image tag/别名 | 说话焦点 | 表情/站位/进退场 | 文本/音频节奏 | 结束与恢复状态 |
| --- | --- | --- | --- | --- | --- |
| 本轮真实语句映射或场景边界 | 真实素材与符号 | 对应角色或无焦点 | 复用的 transform/transition | 默认或该节拍的例外 | 下一句、离场、跳过/回退后的预期 |

默认行为说明一次，仅在发生变化的节拍补行；不要求逐句复制相同参数。表中每项落到真实调用与可观察结果，Writing 的原文/剧情和 Image 的素材责任保持原约定。

## 说话者聚焦

1. 建立 Character 标识到实际显示 tag 的映射。`Character(image="角色tag")` 与 `renpy.get_say_image_tag()` 提供当前发言者关联；显示姓名、文件名和 image tag 各自独立。`show ... as ...`、同角色双实例及指定 layer 按实际映射处理，只作用于本轮管理的在场立绘。已有 Character 的 image 参数还会参与图像属性处理，修改前检查相关 say 属性用法。
2. 自动聚焦需要共用联动逻辑：在台词开始/重新显示时同步目标焦点，并让显示侧应用对应颜色及更新机制；仅查询 tag 或绑定 image 参数不会自动变暗。优先复用当前实现，新增时用最小 Character callback/显示更新配合 ATL，保留既有配音、文字音效等回调行为，避免每句手工插入重复的聚焦语句。
3. 用 `matrixcolor` 调亮度，不用降低立绘 alpha 代替压暗。可从 `BrightnessMatrix(0.0)` 正常色与轻微负值开始调校；渐变两端保持相同矩阵类型及组合顺序，显式给出初始值。现有场景色调与焦点矩阵组合使用，避免覆盖夜景等既有效果。具体亮度与时长由当前画幅/素材观察确定，不把示意参数当作验收阈值。
4. 焦点覆盖整句及等待点击期间。Character 的 `begin` 是整句开始，`show` 是每个文本分段开始，`show_done` 是该段提交显示后；它不表示打字结束。`slow_done` 表示渐显结束，此时继续保留说话焦点；`{w}`/`{p}` 分段和同角色连续发言保持焦点稳定，避免每段重复闪暗。普通结束、读档、回退的处理按当前 SDK 事件语义分开，实际观察相邻句切换有无闪帧。
5. 焦点尽量由当前台词和显示对象推导；确需保存中间状态时使用可保存/回退的 store 变量并以 `default` 初始化。主菜单、历史记录和其他 screen 的预测/重算只展示，焦点逻辑不推进剧情或外部任务。离场/清场后释放本单元的焦点；读档/回退重新呈现当前句时与其实际说话者同步，避免沿用未来台词的焦点。

| 台词情况 | 缺少专门约定时的行为 |
| --- | --- |
| 在场 A 发言，B 旁听 | A 正常色，B 轻微压暗；打字结束后保持，B 发言才交换 |
| 旁白、无绑定或画外发言 | 在场人物回到正常色，不猜测某张立绘对应声音；画外角色保持画外 |
| 多人同时发言 | 按明确参与者映射聚焦多个 tag；只有群体称呼而无映射时采用无焦点，不随意挑一个人 |
| 隐藏身份/内心独白 | 沿用正文视角与已公开映射；聚焦会泄露身份时采用无焦点 |

## 文字渐显与阅读节奏

先诊断再改设置：记录有效 `preferences.text_cps`、旧 `config.default_text_cps` 定义、Character/文本样式的 `slow_cps`、局部 `{cps}` 等标签、当前快进状态和 say screen。`text_cps = 0` 表示即时显示；screen 保留 `text what id "what"` 以接入原生对话行为。仅凭整句出现的现象不直接归因于缺少 `what` id。

新项目没有既定设置时，可用下面的原生默认值作为体验起点，速度单位为字符/秒：

```renpy
default preferences.text_cps = 40
```

- 复用设置界面的 `Preference("text speed")` 控件，确认有效范围包含即时显示；沿用现有 Character/screen，保留点击补全文、继续阅读、自动播放和快进。无既有调节入口时补最小原生控件，文字音效若启用则纳入音量/静音控制。
- 同一默认值通常保留玩家后来选择；更改 `default preferences...` 的默认值可能重新更新偏好。为既有工程补配置时先比较已有默认声明和实际偏好，明确是否迁移；沿用玩家已选择的速度，配置迁移按本轮明确范围处理，保留旧持久化数据。演出流程中不逐句强设速度，也不以清空 persistent 解决显示问题。
- 局部 `{w}`、`{p}`、`{cps}` 只服务已存在的叙事停顿/节奏；适配忠实改编时保留可见原文及字面花括号语义。增删 say、分页或改变执行结构仍按兼容约定评估，文字渐显不构成改写正文的许可。
- 使用原生慢速文本机制，不另建 Python 逐字符循环。逐字音效是可选项，核对文字结束、点击补全、跳过、静音及离开场景后的停播；音效结束与说话焦点结束是不同事件。

## 图像与镜头

1. Image 的文件、Ren’Py image 名、用途及 tag 分别映射；读取其交付推荐而非猜文件名。背景按基准选择 cover 裁边或 contain 留边；立绘通常等比 contain，按可见包围盒/脚底基线对齐，不以拉伸画布修比例。
2. `scene` 清指定层，`show` 同 tag 替换。表情变更通常 `show <同 tag> <新属性>`，保留站位；需要重置 transform 时显式给出。不同角色需要不同 tag；同一角色双实例使用明确别名及独立清理。
3. 连续的 scene/show/hide 准备好后执行一次对应 `with`，得到整体转场；有意分段才分别转场。CG 若替换整个场景，退回时重建应有背景/人物/表情，不假定旧显示自动恢复。
4. 补图或道具特写只占约定区域；图层、zorder 与点击覆盖明确。字体和文字放在 GUI 中时保持可读与可交互，不以整页背景图替代控件。
5. 测实际窗口长宽比、文字框/姓名框/选项、透明边缘与角色相对身高。静态图片检查不证明真实场景显示正确。

## 音频

| 用途 | 接法 | 核对项 |
| --- | --- | --- |
| BGM | music 通道；按意图 loop/noloop，切曲 fadeout/fadein | music 默认循环；同曲跨单元续播可用 if_changed，避免重复进入重头播放 |
| 单次音效 | sound 或项目现有通道 | 普通同一通道新 play 会替换上一声音；重叠需求才使用合适通道 |
| 环境循环 | 复用专用普通通道；必要时在 init 注册到合适 mixer | 入场循环、离场停播、重复进入/回退、受对应用户音量设置控制 |
| 临时叠加音效 | 仅确需叠播且无需独立 stop/queue 时使用特殊 audio 通道 | 它的行为与普通 sound 通道不同，别拿来播需管理生命周期的环境长音 |
| 配音 | 依据 voice 及角色语音设置 | 句子对应、推进/跳过后的停播、自动播放和静音；无配音时不虚构文件 |

音乐使用表应已有触发节拍、持续范围、循环、相对音量和退场方式。只给了一堆曲目时先补这张表，参见 [音乐准备](../../renpi-initialization/prepare-music/SKILL.md)。避免为一次演出覆盖用户持久音量偏好。跨场景保留 BGM 与场尾停播是两种不同约定，按实际叙事采用。

## ATL 与转场

- 将站位/缩放、一次性入退场、说话焦点与持续微动分开组合，明确各自拥有的属性。切表情保留站位和焦点，按意图直接替换或短溶解；只换脸时沿用显示生命周期，不重播入场。
- 普通进退场优先 `show`/`hide` 配合 `with dissolve`；需要走入感时才用 ATL 位移加透明度。多项同时变化先准备再执行一次整体转场；移动已有角色用适当的 move/ease 转场，区分首次入场与已有位置变化。
- ATL `on show` 是首次显示该 tag，`replace` 是同 tag 替换；它们与 Character 文本回调的 `show` 事件不同。采用 `on hide` 退场时注意 `scene` 清层不触发它；清场用场景转场或显式 hide 的节拍，检查离场确实完成。
- `parallel` 的并行块分配不同属性；同属性竞争不是可靠效果。`repeat` 放所在块末尾，持续动画由显示生命周期结束。
- 运动优先 Ren’Py ATL/transition，而非 Python 循环和 sleep；明确时长、起点、终点及用户推进后的状态。
- pause 是否允许点击打断按目的决定，长不可跳过停顿应有具体叙事理由。检查快进/自动/回退后的终态，动画不绑住必需控件。
- 沿用用户的减少动态/转场偏好；若新增持续呼吸、震动或镜头运动，提供静态或减弱方式，仍保留可辨认的发言提示与正确站位。需要复杂镜头、LayeredImage、影片或 shader 时再查专项文档，不预设每个单元都使用它们。

## screen 与状态

持续信息用 show/hide screen；需等待用户完成的局部交互用 call screen 与 `Return(value)`，返回后立即读取 `_return` 并走已定义路径。故事选择优先接既有选择系统，而非再做一套分支状态。

screen 可能在预测与重算中多次求值：显示表达式与 Python 块只计算展示；文件写入、制作派发和业务状态推进留在显式业务动作。按钮 action 也只调用现有经过身份/幂等校验的业务入口；`nopredict` 不代替该边界。临时屏幕离场隐藏，modal、焦点、键盘/鼠标、文字溢出与窗口缩放按 GUI 要求核对。

可变剧情状态由 `default` 初始化；角色、固定配置与正文常量遵循已有 `define` 约定。保存只承诺 SDK 可序列化且项目已验证的状态；外部资源句柄和进行中的制作任务保留在程序侧。
