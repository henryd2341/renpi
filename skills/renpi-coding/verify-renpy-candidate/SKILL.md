# 验证、接入与交接

进入条件：[完整 RPY](../implement-renpy-scene/SKILL.md) 已交付。沿用 [Coding 边界](../references/coding-contract.md)，检查范围按本轮变更决定，避免每次重跑全部剧情。

执行前读取 [用户约束与执行范围](../../renpi-initialization/references/project-contract.md#用户约束与执行范围)。下文列出验收所需证据；用户暂缓的动作保持待验证，包括提交工具内部的编译/lint。读取旧报告或用户确认基础流程通过，不自动触发补测。

## 1. 在隔离候选工程执行静态检查

准备工程先执行 [验证工作区与资产引用](../../renpi-initialization/references/project-contract.md#验证工作区与资产引用)：大文件与媒体资产只用软链接，独立可写输入和存档另行隔离；使用后按引用关系回收工作区，保留报告而非整份资产副本。

公共 GUI 制作任务在执行范围允许时使用 `renpi_submit_candidate(job_id)`，由
[桥接交付契约](../references/bridge-contract.md#制作与交付) 的公共策略校验。
下列手工命令用于独立候选工程，不替代公共提交工具的结果。

核对候选的真实源码、编译依据、素材、调用方与配置构成完整工程。冻结输入身份/版本，由程序/工具记录真实文件证据；源码变化后重做受影响检查。修订需要的上一已接入 RPYC 按兼容约定带入隔离构建副本，原件保留。

先读当前 SDK `cli.html#compile` 与 `cli.html#check-script-lint`。本版 Windows 命令形态如下，使用实际选定 SDK 和**候选项目根目录（含 game/）**，不是传入某个 RPY：

```powershell
# $sdkRoot 是本轮已核定的 SDK，沿用显式选择而非重新猜测安装。
$sdkPython = Join-Path $sdkRoot 'lib/py3-windows-x86_64/python.exe'
$renpy = Join-Path $sdkRoot 'renpy.py'
# $candidateRoot、$checkSaveDir 由当前任务提供，分别为隔离工程及其检查存档目录。
& $sdkPython $renpy $candidateRoot compile --savedir $checkSaveDir
if ($LASTEXITCODE -ne 0) { throw 'RenPy compile failed' }
& $sdkPython $renpy $candidateRoot lint --error-code --savedir $checkSaveDir
if ($LASTEXITCODE -ne 0) { throw 'RenPy lint failed; inspect report' }
```

其他平台按当前 `cli.html` 的启动器调用同样命令。读取实际输出与日志，记录版本、命令、退出码及报告路径。lint 的默认退出行为与 `--error-code` 有区别，判定时同时读取报告。编译会写 RPYC，默认还可能清理孤立 RPYC；lint 也经过加载/init，可能写缓存。它们不是只读分析，执行前确认 init 不连真实制作/外部状态。

编译/lint 之外核对：入口存在且出口可达、重复符号、素材存在与格式、分支/共享引用、资源映射、遗漏正文与玩家权限、必要图像/声音被正确使用。动态引用可能超出 lint 分析范围，需要实际映射与运行证据。

## 2. 只运行受影响场景

| 变更 | 必需追加检查 |
| --- | --- |
| 首次交付/启动脚本或启动条件变化 | 从另一工作目录调用交付脚本，确认启动目标工程并进入预期入口；核对缺失 SDK 时的明确诊断与非零退出码 |
| 新单元/调用链/选择 | 从真实入口阅读至停止点；调用返回、合法选项/返回值、下一入口与重复进入 |
| 图像/立绘/CG | 实际画面、表情与站位、比例/裁边/透明、遮挡和离场残留 |
| 说话焦点/Character 映射/共用回调 | 多角色交替、同角色连续句及分段、旁白/画外音、读档/回退后的焦点；共用修改取样实际调用场景 |
| 文字速度/say screen/文本标签 | 有限速度渐显、点击补全文与下一句、即时显示、偏好保持、快进/自动、长中文与分段 |
| 音频 | 实际听到正确曲目/时机，循环与切换、静音/音量、重复进入和退场 |
| ATL/转场/屏幕 | 实际动画终态、快进/自动/回退、窗口尺寸、焦点与操作、屏幕清理 |
| 正文修订/保存相关 | 适用旧档落点、正文版本、回退、调用栈与当前绑定的区别 |
| 接入相关 | 加载真实候选、正确衔接点、阅读位置恢复、失败撤销与保留旧成果 |

涉及演出基线时执行 [动态验收场景](../../renpi-review/references/presentation-checks.md#动态验收场景) 中的适用项，并记录场景编号/真实入口、操作、预期与实际、候选版本及观察证据。首次组合验证使用隔离的双人短场景或现有等价片段；只改一个效果时选对应场景及关联恢复检查。核对共享调用方，保持正文权限与用户进度。矩阵是 Coding 自验依据，Review 未启用时同样适用。

启动检查与本轮场景检查共用一次运行，通过交付脚本进入，不另起手工命令掩盖入口问题；仅有脚本文件或语法检查结果时，启动状态仍为待验证。只有措辞变化时仍做本候选编译/lint/引用/入口及接入加载确认；无需从开头重播全篇。行为依赖图片、音频或窗口时，静态检查和播放日志不代替可见/可闻验证。

检查使用独立工程、保存/持久化目录与外部调用隔离，确保不提交真实选择、不触发真实制作、不污染用户阅读进度。`--savedir` 只解决一部分存储路径，其他程序配置及外部调用仍要核对；复制整个项目不自动代表隔离完成。需要唯一创作 GUI 时，按项目受控衔接阶段串行安排。

缺运行设施的项标记待验证并保留已完成结果；不以假回执完成门槛。技术错误按当前单元额度修复，剧情/图片问题返相应角色；每轮只修明确问题与受影响检查。

## 3. Review 与真实接入

公共桥接任务核对分支当前 `job_id` 后使用 `renpi_submit_candidate`，提交受阻先按 [恢复顺序](../references/bridge-contract.md#提交受阻与恢复) 处理。按 [交付凭据](../references/bridge-contract.md#交付凭据) 区分产物、ready 候选与已接入结果；已有程序记录可作为只读证据，模型自述或手填状态均非加载 ACK。

启用 Review 时按 [审查委派](../delegate-production/SKILL.md#review-与返修) 提交当前候选与证据。通过、需修改、受阻分开处理；修复后核对版本并取得有效复审，过期报告不通行。

请求接入前由程序再核对候选版本、证据、取消/补充状态与可用衔接点。通过实际接入入口操作，确认内容已加载且阅读位置正确恢复；失败保留旧成果与候选诊断，执行已有撤销机制。Agent 不直接复制文件进运行区来绕开接入，也不手写 HEAD/绑定。

## 4. 留下下一轮能用的交接

更新已有工程交接：本轮实际产物/入口/出口、启动脚本路径与准确运行方法（适用时含双击方式）、SDK/配置前提与日志位置、共享定义与素材映射、采用的 SDK 依据、验证/Review 引用、接入结果、具体待办。注明启动脚本的实际验证结果，报告明确区分“草稿已交付 / 候选已验证 / 已接入可读”。

记录校验报告的实际 `ignored_checks`，区分 Agent 本轮执行、现有程序记录和用户观察。单项目基础流程通过不代表跨项目复用、完整异常恢复、旧档/回退或 GUI 全场景通过；未执行项保留待验证。

Writing 的 [文本记忆](../../renpi-writing-plots/remember-story-text/SKILL.md) 根据实际采用结果进入有效前情；旧候选记忆保留其身份，不污染下一轮。工程交接记录媒体/代码，文本记忆只记录值得延续的故事内容。完成本单元后停止，不自动制作未选路线。
