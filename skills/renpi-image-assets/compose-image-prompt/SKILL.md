# 编写模型专属提示

进入条件：[后端、模型及配置](../resolve-image-pipeline/SKILL.md) 已核实，已读取其专属资料。本阶段共用画面事实，不共用一套最终提示词。

## 根据模型组织表达

- 标签友好的二次元模型：先用该版本实际识别的角色/人数、外观、动作、服装及场景标签表达主体，再用适合其编码能力的简短描述补空间关系。质量、年份、评分标签只按对应模型卡使用，不跨家族粘贴词包。
- 标签与自然语言混合模型：标签承担已知概念，句子承担“谁对谁做什么、物体在何处、哪里露出或保持不变”。两部分互相校验，人数、左右、服装和代词保持一致；模型或节点的 token 限制按实际版本检查。
- 自然语言理解较强的模型：用清楚的场景/构图/关系句组织，说明每张参考图的角色及编辑不变量；准确描述局部修正而非叠加强调词。也要检查复杂关系，能力强不代表一次出图自动满足所有约束。

类别选择以模型资料和实际效果为准；SDXL、Anima、Krea 2、Z-Image 各自仍有独立规则，不将前四种统称“只吃标签”，也不把所有后端上的同名模型视为同一版本。

## 保留内容，转换语法

1. 将画面说明中的硬性要求逐项落入提示或接口支持的参考/控制条件；重点主体与关系保持清楚。角色标签来自已知依据；已有标签可用则保留，存在冲突时说明并针对性调整。标签用模型词表或已验证样例支持的写法，未知概念用明确描述补足，避免生造英文组合当标准标签。
2. 参考图按身份、风格、构图、编辑目标分别说明。裁切看不见的细节保持为参考设定，不强行要求本图展示全身所有特征；切换模型时重新适配描述，素材基准本身保持不变。
3. 负面/排除内容只放到实际支持的机制里。无独立负面槽时，用简洁的正向构图与必要限制说明表达；不把 negative prompt、`{}`、`[]`、括号权重、`BREAK` 或 LoRA 字符串当作通用模型语言。
4. 具体可见文字逐字给出，并说明位置与用途；模型可能写错时交付后按字检查。没有图中文字需求时保持画面纯图，不凭“补充图”自行加标题或字幕。
5. 控制 prompt 长度时先删冲突、冗余和无依据质量词，保留关键人物属性与关系。实际 tokenizer/节点限制可查时检查；没有可靠计数工具就说明未测，不套旧版本固定上限。

## 参数与提交前核对

采样器、调度器、steps、CFG、denoise 等由实际工作流/接口及其已验证配置控制。仅修改任务或模板明确开放的映射项，提示编写不顺手覆盖采样参数；跨模型迁移时重新确认支持字段，不搬整包设置。

交付实际正面提示、适用的负面/角色提示或编辑说明、参考映射、参数变更及模型依据。没有的槽位省略，不伪造空字段为接口能力。

提交前核对人数、人物属性、视点、左右/遮挡关系、画面时刻、风格和 UI 安全区，以及负面是否反向排除了必需内容。注意多义词：排除图中文字宜明确为 lettering/typography，不在需要信件的图中笼统排除 letters。完成后进入 [图像制作](../produce-image-assets/SKILL.md)；提示准备完成不等于图片完成。
