# 执行图像制作

进入条件：画面说明、模型专属提示、输出范围与依赖已明确。执行前回查 [Image 边界](../references/image-contract.md) 及已选后端指南，使用实际提供的工具，不根据技能名称编造调用接口。

## 提交与取回

1. 先核对同一需求是否已有合格图或在途/未知结果。可复用则交检查；在途先查原请求。返修明确原图、当前候选及本轮唯一修改目标，避免重新随机生成整套差分。
2. 编辑前实际查看输入，参考素材只传本次所需，并保持身份/风格/构图等角色映射。按工具实际支持方式传图和遮罩，核对真实输入引用；提示中的文件名本身不证明图像已经传入。
3. 提交前保留本次任务、目标后端/实例、工作流/模型依据和实际参数；提交后保存工具返回的请求或作业引用。无异步作业 ID 的工具按其真实同步结果记录，不制造队列状态。
4. 已有调用次数与并发约束继续有效。新方向先做代表图验证，再扩展批准范围内差分；同角色组共享已确认基准，seed 相同也仍逐张核对。
5. 按实际后端状态取回输出，检查它属于本任务和所需输出节点/结果项。复制到分配的项目目录，保留输入和来源；不长期依赖服务缓存、临时下载地址或生成工具的默认存储区。

## 失败、未知和取消

- 参数拒绝/缺节点/缺模型：记录真实错误并核对当前字段或依赖。先修正本次映射，不靠换模型、安装插件或启动新服务绕过配置。
- 超时/断连/客户端退出：先核对原提交与已有结果，未知仍为未知；对有费用或外部副作用的请求也不盲目重试。缺少查询能力时将证据与原请求交 Coding 决策。
- 取消仅针对明确归属且后端支持的请求；共享队列全局中断不当作本任务精确取消。晚到图保留原归属并标待处理，取消本地等待不宣称后端已停止。
- 视觉不合格：由 [图像检查](../review-image-assets/SKILL.md) 指出具体偏差，优先局部编辑或一次有针对性的提示修正，沿既有次数边界执行。没有配置时先交代表候选与问题，不自行无限抽图。

完成标准：结果已实际取回、可定位，或执行状态与缺口如实交付。成功取回的图片进入 [检查与交付](../review-image-assets/SKILL.md)，生成成功本身不代表视觉合格。
