# 读取图像任务与视觉依据

进入条件：Coding 已分配一项图片任务及输出范围。读取 [Image 边界](../references/image-contract.md)，本阶段先看资料和已有图，不急着填提示词。

## 明确这张图要表达什么

1. 读取任务对应的实际源文/正文片段、适用人物设定、视觉基准和已有资产记录；不以整个 TUI 历史或另一条路线填补未知细节。
2. 将任务分成场景插图/CG、环境背景、局部/道具补充图，或 init 基准/立绘/差分。场景图选择一刻及其可见关系，而不是把前后所有动作塞进一帧；补充图明确它补充哪项信息。
3. 明确主体数量、动作、表情、服装/持物、环境与时段，区分必须遵守的故事事实和可自由发挥的装饰。关键外观或剧情事实缺失时交 Coding 澄清，其余根据已定风格作最小必要补全。
4. 从游戏用途确定画幅、景别、视点、主体位置及 GUI 遮挡安全区。安全区指后期叠加界面的留位，除任务明确要求界面实图外，图片本身保持纯图，不绘制对话框或按钮。场景背景需要为后续立绘留空间时明确说明；CG 已含人物时避免再按空背景目标制作。局部图的裁切应服务信息表达。
5. 查看现有候选、基准和原图，分别标记身份参考、风格参考、构图参考、编辑目标和遮罩。实际查看图像，不凭文件名断言内容；参考图中的附带人物/服装/文字不自动全部进入本图要求。

## 形成后端无关的画面说明

保留用途/来源时刻、必需主体及关系、视觉基准、构图与安全区、应保留/应改变内容、技术要求、参考图作用与结果归属。这是语义输入，不是直接发送给所有模型的统一提示模板。

- 检查符合需求的现有图，能直接复用时交 [检查与交付](../review-image-assets/SKILL.md)；用户明确重绘则遵从该要求。
- 编辑已有图时，写清只改哪些内容、哪些保持不动；沿图像编辑路径处理，而非重新生成后声称保留成功。
- init 提前任务只需要该图片的依赖；缺基准时可产出基准候选，方向待用户确认。尚无剧情段落时依已确认设定制作基础图，不臆造未来事件。

完成标准：有可执行的单图或明确差分组需求，来源、变更范围和用途清楚。进入 [后端与模型确认](../resolve-image-pipeline/SKILL.md)；明确可复用的项无需新生成。
