# Image 的职责与素材归属

沿用 [Agent 分工](../../../docs/wayfinder/tickets/RP-006.md#resolution-comment--2026-09-19) 和 [素材契约](../../../docs/wayfinder/tickets/RP-007.md)。本轮扩展的是多后端/多模型的技能导航，不代表这些服务已经安装、可调用或经过真实出图验证。

## 任务边界

- Coding 指定目标任务、用途、已采用的剧情/设定依据、视觉基准、文件范围及完成条件；Image 读取相关内容并制作图片，不改写故事、玩家选择或运行状态。
- 主任务为场景插图/CG 与补充图。init 的基准图、缺失背景、立绘和差分也可提前委派；已有 [立绘准备](../../renpi-initialization/prepare-character-sprites/SKILL.md) 的透明与显示约束继续适用。GUI 矢量设计/页面实现仍属于 [GUI 技能](../../renpi-initialization/design-game-gui/SKILL.md)，不以一张界面位图替代它。
- 从当前有效依据取画面事实，尤其是人物在场、衣着、物件、时间和可见信息。草纲或未来情节只有明确作为本图依据时才采用，并标记候选用途；画出了某事不表示该事已发生。
- 已有工具和服务按实际能力检查，费用不设为本流程必问题。仅调用已启用来源，环境、模型和节点保持现有配置；安装、升级、启动服务或改变后端策略另由 Coding 协调具体操作。

## 资产与文件

图像保存到任务分配的创作区域。一般共享基础素材位于 `authoring/shared/`，路线专属素材位于 `authoring/branches/<已有分支标识>/`，最终按项目既有布局处理；`game/` 与业务状态由 Coding/程序接入。

原件与新候选分开，重绘、去背、裁切和编辑保留输入；已有同名文件先核对归属，不直接覆盖正在采用的图。每份文件只有一个写入者，交回或返修时明确交接。

沿用已有资产清单和任务引用；没有时在分配目录附一份短的 `image-delivery.md`，至少记录：

- 任务及用途、共享/分支归属、对应剧情时刻或 init 清单项、依据及视觉基准。
- 原图/参考图及各自作用，最终推荐文件、候选/差分关系、语义命名与预期显示区域。
- 实际后端、模型标识/版本、工作流依据、实际提交的提示与支持的参数；工具隐藏的信息记为未公开，不补猜。
- 后端返回的请求/作业标识（如有）、结果状态、技术与视觉检查、返修内容和未决项。凭据值和含密钥的请求头排除在记录之外。

这些是交付与追溯材料，不是新任务状态机；稳定身份沿用实际程序记录。文件名、生成时间、seed 或 prompt 相同都不单独证明是同一个资产，也不保证人物一致或精确复现。

## 前后阶段连续性

init 提前调用和日常剧情调用共用上述资产记录。进入下一阶段先检查已有产物、适用基准和在途任务；需求未变则复用，需求改变则保留旧图并重审或准备新候选，不重置任务或重跑整套 init。

任务取消、响应超时与后端实际停止分开记录；晚到结果按原任务归属保留，由 Coding 决定采用。只对明确属于本任务的操作作查询/取消，不清空共享队列或终止其他工作。

原文件存在、请求被接受、生成完成、视觉合格、实际运行接入依次是不同证据。任务所需视觉判断缺失时标待检查；必需图不因失败自动变可选或变成纯文字方案。
