# 检查并交付图像

进入条件：实际图片已取回，原任务说明与基准可读。先查看图片，再判断；文件名、参数与生成工具的成功消息都不是视觉验收。

## 分开检查

| 检查面 | 核对事项 |
| --- | --- |
| 技术 | 文件真实格式、可解码、尺寸/画幅；需要透明时查看真实 alpha 与深浅底边缘，排除烘焙棋盘格和全不透明输出 |
| 剧情 | 正确的人物数量、场景时刻、服装、道具、动作与人物关系；没有增加未发生情节或把计划画成事实 |
| 基准与组内一致性 | 角色辨识、外观细节、画风、服装/伤势连续性；差分间人物比例、姿势基线及不应变化的部分 |
| 构图与可用性 | 视点、主体焦点、左右和遮挡关系、肢体完整度、UI 安全区；需要保留脸/道具的位置没有被错误裁切 |
| 文字与局部编辑 | 可见文字逐字正确；局部修正之外的人物和构图保持要求，未引入额外标志或残留背景 |

立绘另遵循 [立绘准备](../../renpi-initialization/prepare-character-sprites/SKILL.md) 的等比/基线检查。背景或 CG 按目标画幅与 GUI 遮挡区做必要预览；静态合成只证明构图，实际 Ren’Py 显示检查仍由 Coding 整合后完成。

缺少技术检查或视觉观察能力时，将对应项标待检查，不用“看起来提示正确”替代图像判断。基准候选交 Coding 展示给用户定向；既有基准下的普通图按任务验收，不强制逐张重新审批。

## 有界返修

把偏差写成可执行修改，例如“人物右手应持信，保持脸和服装”，而非“再好看一点”。判断是提示关系、参考传递、工作流能力、图片局部还是显示布局问题，再回到相关步骤；运行布局问题不自动触发重绘。

比较返修图与原候选及基准，确认改好了目标且未破坏保留项。保留候选和修改依据，沿本任务额度执行；仍有实质缺口就交回 Coding，不用选一张勉强合格图掩盖。

## 交付与下次读取

按 [交付记录](../references/image-contract.md#资产与文件) 给出推荐文件或明确差分集合、用途/剧情位置、共享或分支归属、模型/后端/参考及实际提示、技术与视觉结果、未决项。提供实际图片预览，不让 Coding 从输出目录最新文件猜选图。

init 提前产物带回原清单项与基准状态；后续任务读这份记录，核对用途/基准仍适用后复用。图片就绪只解除相关素材缺口，不自行标记整个 init 完成或让剧情跳过等待。

完成标准：图片及其适用范围明确、检查证据与限制可追溯，下一步整合所需信息齐全。由 Coding 进行运行接入；未选图、未确认基准和晚到候选维持各自状态。
