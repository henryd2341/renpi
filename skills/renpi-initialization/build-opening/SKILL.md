# 制作可阅读起点

创建或适配 `game/` 后，按 [公共桥接契约](../../renpi-coding/references/bridge-contract.md#初始化接入) 调用 `renpi_bridge_setup`，将统一客户端纳入工程；选择点使用公共 `renpi_choice`。已有私有触发器先记录迁移边界，避免两个消费者同时驱动同一位置。

进入条件：用户已确认筹备方案，[必需创作基础](../prepare-foundation/SKILL.md) 已就绪。读取 [项目边界](../references/project-contract.md)，复用项目实际的新建/适配、制作与接入能力。

## 制作与整合

1. 按方案明确首个单元的内容和自然停止位置。完整文本按原文自然边界呈现；自由创作通常推进至下一用户输入点，而非无限续写。
2. 使用已有模板建立或调整脚本骨架与公共定义，接入 [GUI 制作](../design-game-gui/SKILL.md) 交付的已确认界面代码和资产。设计候选留在设计区，避免改用默认主题覆盖选定方向。实际程序维护项目身份与原始分支，技能不自行编造状态字段。
3. 启用 Writing 时委派其产出独立基础 RPY 正文；未启用时 Coding 按同样剧情约束兼任。Coding 负责工程整合、转义、角色冲突检查、素材引用与流程控制，技术整理不扩大剧情修改范围。
4. 保持全局标签、定义和界面符号可共存；分支文件夹不是 Ren’Py 命名空间。使用既有执行结构与接入方式，涉及旧存档的内容调整保留已确认兼容边界。
5. 原文内容通过来源索引定位，记录实际采用范围；分片边界不代替叙事停止位置。按交付的音乐使用表和立绘布局映射接入音频触发、图像声明及站位/差分，复用现有符号，避免从文件名临时猜测用途。

## 验证与接入

以下是阶段验收要求，执行前按 [用户约束与执行范围](../references/project-contract.md#用户约束与执行范围) 核对本轮允许的动作。暂缓的检查保留待验证状态，照常保存已有成果；需要换会话时交接进度与规则。

准备检查工程时遵守 [验证工作区与资产引用](../references/project-contract.md#验证工作区与资产引用)：大文件与媒体资产只用软链接，工作副本按生命周期回收，正式来源与必要证据保留。

- 运行实际 SDK 编译、lint 和首个单元所需的运行检查；启用 Review 时取得当前候选对应的有效报告。静态通过、Review 通过与实际 GUI 可读分别记录。
- 通过现有接入机制发布经验证的成果，确认实际加载与首个单元可阅读；已有运行内容和存档按项目规则保护。
- 按 GUI 技能交付的运行核对项检查约定页面、字体、长文本、控件状态和真实操作，呈现实际界面预览或截图。SVG 候选获确认和 SDK 编译通过，都不单独代表 GUI 已可用。
- 存在音乐/立绘时，执行 [音乐运行核对](../prepare-music/SKILL.md#交回开场整合) 与 [立绘实景核对](../prepare-character-sprites/SKILL.md#交付与预览)：听到正确时机的曲目与切换，看到正式图的比例、透明边缘、差分及文字框遮挡；覆盖适用的音量/静音、重复进入、读档/回退以及承诺的窗口尺寸。静态预览、播放命令日志与真实可闻/可见结果分别记录。
- 修复沿用当前单元已有额度，重新委派不重置额度。发生失败保留产物和诊断，只重验受影响部分。
- 若实际的新建/适配、验证或接入入口缺失，列出缺少的能力及已保留成果，停在该依赖处；不以测试夹具、模拟加载确认或手填业务状态代替成功。

## 结束条件

首个可阅读单元与方案一致，来源范围可回查，GUI 的必要页面与操作实际可用，必需音频与立绘按已定映射在真实单元中得到核对，当前成果具有所需验证结果且实际接入可读。未做的必需检查维持待验证，而不是报告阶段完成。

记录成果路径、实际验证和阅读入口，进入 [交接正式创作](../handoff-creation/SKILL.md)。
