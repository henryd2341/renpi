# 逐项澄清需求

进入条件：已有 [项目与环境扫描](../scan-project/SKILL.md) 摘要；已明确的答案直接继承，环境缺项单独记录。

## 询问方式

先简述已找到的依据和待澄清事项，再一次聚焦一个当前可决定的问题，等用户回答后继续。可提供建议与取舍，但建议和用户决定分开记录。

事实先自行查文件或环境；询问聚焦用户选择、缺项与歧义。用户只给点子时先帮助其逐项明确需求，之后才整理完整方案，不先自行补出整套角色和开场当作既定内容。

## 需要厘清的适用事项

- 创作模式、资料来源与采用依据：完整文本改编还是自由创作，冲突材料以什么为准。
- 故事方向、角色和用户扮演身份。
- 呈现风格与交互方式，包括必要 GUI 的页面/操作范围、已有界面的复用或重做要求；纯文字模式也保留 GUI 需求。
- 首个可阅读单元的内容范围。
- 尽量完整的已知准备清单，以及本次必需范围。先展示已知项，再确认取舍，避免先按开场缩减清单。

完整文本改编默认忠实于原文，缺少呈现细节与改变原作剧情分别讨论；自由创作中的未定内容只有在用户明确委托后才由 Agent 决定。

根据扫描缺口补问具体的内容选择，而非机械新增一套必答问卷：

- 原文：多版本采用顺序、提取乱码的正确含义，以及章节归属等实际歧义。规范化编码/换行和无损有序分片属于技术整理；删节、OCR 修字、改写或重排另明确依据。
- 音乐：已有固定用途，还是委托 Agent 按场景编排；区分曲目已提供与用途已决定。明确委托后由 Agent 完成普通曲目映射，只有叙事方向歧义再询问。
- 立绘：需要哪些角色/差分、全身或半身、构图与裁切要求；没有现成透明素材时确认制作范围，不把“用户必须先备好素材”设成默认前提。

已知资产缺口先展示，用户的内容选择与 Agent 可自动完成的格式/适配工作分开记录；缺口处理及产物最终纳入筹备方案。

工具属于内建能力，费用不在本流程需求考虑范围。“其他补充内容”是可选项：用户另有要求时记录，不设置固定工具选型、预算或费用问卷，也不以缺少这些回答阻塞收口。

用户提出停用 Image/Review、暂缓测试等要求时，按 [用户约束与执行范围](../references/project-contract.md#用户约束与执行范围) 记录具体动作及有效期，只澄清会影响执行的歧义。区分本轮要求与用户确认要写入项目 `AGENTS.md` 的长期要求；已有明确决定直接继承。

## 结束条件

每个适用事项均有明确答案、明确不适用，或用户明确委托 Agent 决定；影响方向和范围的冲突均已解决。记录被委托事项与采用的决定，普通技术实现细节由 Agent 处理，未知未来剧情留到后续。

将确认结果和依据交给 [筹备方案](../plan-initialization/SKILL.md)。环境缺项继续保留，不把需求清晰等同于环境已经就绪。
