# 交接正式创作

进入条件：[可阅读起点](../build-opening/SKILL.md) 已完成，方案内必需准备就绪，启动阻塞已解决。读取 [项目边界](../references/project-contract.md)。

用户在准备未完成或验证暂缓时要求先换会话，也可使用本文保存规则与进度；明确标为未完成交接，后续接续原阶段。

## 整理交接

优先复用 `authoring/handoff/` 中已有交接文档；没有时建立 `init-handoff.md`。引用筹备方案和实际文件，避免复制一份独立业务状态。

交接需包含：

- 创作模式、采用依据、用户决定与明确委托事项。
- 已完成资料、资产、确认的视觉基准（含 GUI 方向）、首个单元及阅读入口；按 [Coding 启动交付](../../renpi-coding/implement-renpy-scene/SKILL.md#4-留下可复用的启动脚本) 附上实际启动脚本、用法与验证结果；链接 GUI 设计源、正式界面/资产对应及实际运行核对结果。
- 实际验证结果与仍有的限制，区分可选待办和阻塞事项。
- 原文或外部来源引用、剧情接续位置与下一步工作。
- 按适用项链接文本规范化/分片索引与覆盖情况、音乐使用表、立绘差分/布局映射；注明原件和派生文件位置，区分资产检查与实际单元中的试听/显示结果。全篇机械整理不等于全篇已阅读或已制作。
- 在途或结果不明任务的现有身份、状态和待核对动作。
- 公共桥接的安装版本、连接状态和实际选项接入证据；“开场可读”“真实委派可用”“分支接入已验证”分别记录，前两项不代替第三项。接入方式见 [公共桥接契约](../../renpi-coding/references/bridge-contract.md)。

摘要用于导航，原始依据和程序状态继续作为事实来源。交接中排除凭据值。

## 项目规则落盘

将项目根 `AGENTS.md` 作为新会话的短入口，详细资料继续放在已有交接与索引中：

1. 读取已有规则及宿主加载方式，展示目标路径和拟合并差异。保留已有结构与无关内容；首次创建或没有合适位置时使用独立的 `Ren’Pi 项目约定` 小节，后续更新同一处，避免重复追加。
2. 草案仅收录用户确认的跨会话要求：角色启用范围、素材复用/生成边界、测试与运行的执行范围，以及其他项目约束。沿用 [约束语义](../references/project-contract.md#用户约束与执行范围)，本轮暂停事项留在交接，不自动升格为长期禁用；后续规则变更仍先展示差异并确认。
3. 补上真实阅读入口：当前交接、采用的资料索引、制作入口技能及工作区读取规则。用已核实路径，优先项目相对路径；技能位置按当前安装核对。默认目录和示例路径在实际存在前保持为说明，不作为必读文件引用。
4. 写明任务、分支、候选与接入结果以当前程序状态为准。规则文件只保存约束和导航，动态 ID、历史状态及诊断放在可核对的交接记录中，凭据值排除在外。
5. 用户确认后合并写入并回读，核对确认内容与引用目标。宿主停用项目上下文加载或存在遮蔽该文件的覆盖规则时，先说明影响并确认接入方式；有效覆盖规则及其他用户文件保持原有归属。

## 用户确认与新会话

1. 展示简短准备摘要、首个单元的实际入口和项目规则差异，请用户确认正式开始及长期规则；有必需项未完成时明确说明并保留准备状态。
2. 确认后先完成上述规则落盘、成果和待办保存，再提示当前宿主实际支持的新会话入口。默认在同一 TUI 开新主 Agent 会话，并保留 init 旧会话；仅提醒开新会话不算交接完成。
3. 切换前妥善处理在途写入。外部结果不明保留原任务身份核对，换会话不触发重提任务。
4. 新会话核对当前项目及有效规则，按 [工作区读取与约束](../references/project-contract.md#工作区读取与约束) 读取交接、有效全局依据和当前程序状态，再按需读取来源。Pi 1.1.0 的 `/new` 会重新加载项目上下文；其他宿主核对其实际机制，无需搬入全部准备历史。
5. 保持原项目、分支、HEAD、选项绑定、存档与额度。交接失败恢复交接，保留旧会话和成果，不重新执行整套 init。

## 结束条件

正式交接完成时，用户已确认正式开始，项目 `AGENTS.md` 与交接已保存且引用有效，成果足以继续创作，新会话的实际接续结果已说明。若切换需用户操作，报告“准备已完成，规则已保存，等待会话交接”；仅保存未完成进度时注明原阶段及待验证项，两者均不宣称新会话已读取规则。
