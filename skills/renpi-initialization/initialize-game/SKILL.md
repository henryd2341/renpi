# 初始化游戏

你是 Coding 主 Agent。这是 init 的入口，负责阶段顺序、用户确认和交接；具体工作交给下列阶段技能。init 的成果是可开始创作的项目，不是只有一份资料清单，也不是预先制作整部游戏。

## 开始

确认目标项目目录，读取 [项目边界](../references/project-contract.md)，先完成工作区定位与有效项目规则读取。复用项目已有的决定和 init 记录；继续已有 init 时，先核对已完成成果，接续未完成阶段。

按下表逐阶段读取对应 `SKILL.md` 并执行，阶段完成后再加载下一份。技能名称用于组织能力，不代表新增程序接口；直接调用某一阶段时也要检查它的进入条件。

| 顺序 | 阶段技能 | 阶段完成条件 |
| --- | --- | --- |
| 1 | [扫描项目与环境](../scan-project/SKILL.md) | 文件依据、材料冲突和环境实际状态已经列清；环境缺项已说明影响 |
| 2 | [逐项澄清需求](../clarify-requirements/SKILL.md) | 适用需求均已明确、不适用或由用户明确委托决定 |
| 3 | [审阅筹备方案](../plan-initialization/SKILL.md) | 尽量完整的已知清单已展示，本次范围与方案获用户确认 |
| 4 | [准备创作基础](../prepare-foundation/SKILL.md)，按材料类型进入文本、GUI、音乐或立绘子技能 | 必需资料、素材及使用映射、GUI 源码就绪；适用的角色/画风及 GUI 方向获用户确认；运行检查项已交接 |
| 5 | [制作可阅读起点](../build-opening/SKILL.md) | 首个单元已整合、通过实际所需验证并成功接入 |
| 6 | [交接正式创作](../handoff-creation/SKILL.md) | 用户确认正式开始及长期规则，项目 AGENTS.md 与交接材料已保存并回读，当前宿主交接结果已说明 |

## 推进与确认

- 用户确认点是筹备方案、视觉基准（含 GUI 方向）、正式开始。普通整理、生成文件和既定方案内的执行自动推进；GUI 运行核对在开场整合后完成。
- 出现方向冲突或需要覆盖已有成果时，说明具体影响并重新确认；用户修改需求后只重开受影响的阶段。
- 环境缺项不妨碍资料梳理与需求讨论，但依赖该能力的制作步骤保持待处理。已具备工具不等于实际执行成功。
- 材料存在不等于准备就绪：文本要可读可定位，音乐要有使用编排，图像要有用途与显示策略。基础准备交付资产和整合依据，开场阶段验证实际表现。
- 每次停顿只说明已完成事项、当前待决问题或具体缺口及下一步，避免以测试数量代替可用成果。
- 用户暂停或执行中断时保留成果、确认记录与在途任务身份。下次核对后继续，保持原项目与已有内容。
- 执行限制导致必需检查暂缓时保留待验证状态；若需先换会话，使用 [交接规则](../handoff-creation/SKILL.md#项目规则落盘) 保存已确认约束与进度，换会话本身不等于 init 验收完成。

## 收口

清单、素材、编译各自完成都只是阶段成果。按最后一项技能确认首个单元的实际可阅读状态与交接后，才报告 init 完成；未完成项按其影响明确列出。
