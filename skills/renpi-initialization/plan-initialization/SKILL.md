# 审阅筹备方案

进入条件：[需求澄清](../clarify-requirements/SKILL.md) 已完成。按 [项目边界](../references/project-contract.md) 保存文档；这一阶段整理方案，不提前制作游戏内容。

## 方案内容

优先更新项目已有筹备文档；没有时使用 `authoring/handoff/init-plan.md`，已有同名文件先读取并保留无关内容。文档与对话摘要共同供用户审阅，避免只把决定留在聊天历史。

方案包含：

1. **创作依据与决定**：采用的原文、设定和参考来源，模式、角色、扮演身份、呈现与交互方式，以及明确委托 Agent 决定的事项。
2. **尽量完整的已知清单**：资料整理、角色与场景、图像/音频/字体等基础素材、公共定义、界面和首个单元需求。注明材料覆盖范围与尚未知内容。
3. **本次执行范围**：各项区分已有可复用、待准备、可选及随剧情制作，并标出本次必需项；尽量完整的清单不等于本次全部制作。
4. **制作与验收安排**：复用来源、拟新增或修改的成果、视觉基准确认方式、首个单元的内容和停止位置、环境缺项及其影响。列明已确认的角色启用与执行限制，区分本轮要求和待写入项目 `AGENTS.md` 的长期要求；技术检查沿用当前项目能力，费用不单列必填栏目。
5. **待用户审阅的差异**：列出拟覆盖已有成果、仍需用户取舍或相较前次确认发生的变化。

GUI 必须纳入范围，列明已有界面是否适用、缺少的 UI 资产与所需页面；纯文字模式只影响相关剧情插画需求。缺少合适 GUI 时安排 [候选设计与制作](../design-game-gui/SKILL.md)，将 GUI 方向确认纳入视觉基准环节；本阶段确认制作范围，不提前选定尚未展示的样式。

清单每项写明“当前状态 → 处理动作 → 产物/用途 → 完成证据”，区分已有原件与已可使用的成果。例如：

| 已知情况 | 本次处理与产物 | 阶段验收 |
| --- | --- | --- |
| 单一大文本，编码/章节待整理 | [规范化与有序分片](../prepare-source-text/SKILL.md)、完整性检查、来源索引；列出本次整理覆盖范围 | 机械完整性与内容提取质量分别检查，首单元引用可回查 |
| 有音乐但未编排 | [音乐使用表](../prepare-music/SKILL.md)、必要派生音频、播放定义 | 基础阶段检查音频与用途；开场检查实际触发、循环及音量 |
| 需要立绘但缺透明图或显示不合适 | [立绘制作/适配](../prepare-character-sprites/SKILL.md)、角色基准预览、差分及布局定义 | 基础阶段检查透明与合成构图；开场检查实际显示和切换 |

每项注明复用、转换、生成还是等待内容决定；新增工作仍受本次范围约束。源文件可用、映射就绪与运行通过是不同证据，避免写成一个笼统的“素材完成”。

## 审阅与结束

请用户确认方案和本次范围。收到修改意见时更新受影响部分；方向或范围仍含歧义时返回对应需求问题，不重问其余已确认项。

记录用户确认的方案版本或明确内容范围。确认后进入 [准备创作基础](../prepare-foundation/SKILL.md)，在方案范围内自动推进，直到下一用户确认点或具体阻塞。
