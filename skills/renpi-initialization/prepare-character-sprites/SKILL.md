# 准备角色立绘与显示适配

进入条件：已确认角色、立绘用途与本次必需范围，读取 [项目边界](../references/project-contract.md)。角色立绘不是所有模式的默认必需项；一旦纳入本次必需范围，缺图或比例不合适就进入制作/适配，而不是标记为完成。

## 明确需要什么，检查已有素材

1. 从角色资料和剧情列出已知角色、服装、姿势、表情与全身/半身需求，标出本次必需及随剧情制作项；只制作当前批准范围。角色外观、画风和裁切偏好继承已确认基准，新增方向歧义再询问。
2. 记录游戏逻辑分辨率、角色可用区域、对话框遮挡区、单人/多人站位与当前 GUI 设计。立绘宽高比无需等于游戏画幅；目标是人物在指定区域中的构图。
3. 逐张检查画布尺寸、实际透明度、非透明人物边界、画质、姿势与表情对应。PNG 后缀不证明透明；检查是否全不透明、全透明或把棋盘格烘焙进背景。透明边缘在深浅底上预览，关注发丝、光晕、白边与残留背景。

完成标志：已有素材按“直接复用／需去背或修整／需显示适配／需新制”分流，缺口与用途明确；图像存在和显示合适分别记录。

## 缺图或透明背景不合格时主动准备

- 有合适参考图但缺透明立绘：先检查原图，通过现有 Image/编辑/去背能力制作派生资产，保留来源。复杂发丝、半透明饰物和与背景同色的服装需要视觉检查，避免全局删一种颜色损伤人物。
- 没有合适图：按已确认角色资料、姿势与画风准备代表立绘，明确所需透明输出。实际能力只输出带背景图时，将去背与边缘处理作为未完成步骤，不把“透明背景”提示词当作结果证明。
- 展示代表立绘及放入 GUI 版式后的预览，用户确认角色/画风基准后再批量生成服装、表情差分。已有适用确认直接继承；GUI 的多套 SVG 规则不机械套用到每个角色。
- 必需能力缺失时保留制作缺口并说明所需输入或能力；草图和占位图可用于布局试排，但正式立绘就绪需以实际资产为准。

完成标志：本次适用的角色视觉基准已确认，必需立绘真实透明、边缘和人物内容经过检查，派生处理可追溯。

## 等比适配与差分对齐

1. 先确定人物的屏幕目标高度、位置、基线和允许裁切范围。脚底、腰线等基准点按角色构图选择；透明画布底边不自动等于脚底。同角色差分沿用相同比例、基准点与画布/留白约定，或记录逐张补偿。
2. 优先在显示层做统一比例缩放和定位。以人物有效边界估算尺寸时，变换仍作用于整个画布，需补偿透明边距；检查变换后的实际位置，避免仅计算宽高就判定通过。
3. 核对所用 SDK 的 [Transform Properties](https://www.renpy.org/doc/html/transform_properties.html)。`zoom` 等比缩放；指定 `xysize` 时可用 `fit "contain"` 保持比例。默认填充可能拉伸；`fit "cover"` 保持比例但可能越界，并不自动裁剪。需要裁切时单独实现并核对，人物裁到哪里依据已确认构图。
4. 图片源像素、有效人物区域、显示逻辑尺寸分开记录；检查现有 `oversample` 或其他尺寸变换。需要补画布、缩放导出或局部修整时另存派生文件，避免覆写原图。
5. 将所有当前必需差分放入相同站位切换预览，检查头部/脚底跳动、人物忽大忽小、衣装/外观偏移。共用 transform 与同样画布尺寸都不单独证明视觉对齐。

完成标志：每张必需立绘都有明确显示策略，比例自然、基线一致；有意裁切有依据，非预期遮挡已修正。

## 交付与预览

沿用已有资产清单；没有时可在 `authoring/handoff/sprite-layout.md` 记录：角色/服装/表情标识，源与派生路径，画布及人物边界，透明检查结果，基准点，目标区域、缩放/锚点/位移与裁切策略，实际 Ren’Py 图像标识和定义位置，基准确认与预览路径。

基础准备阶段在选定 GUI 的实际宽高比下制作合成预览，覆盖当前必需的单人/多人站位、极端宽高素材及差分切换对照，展示给用户；预览和正式运行分别记录。图像声明、站位 transform 与资产交给 [开场整合](../build-opening/SKILL.md)，依据项目已有命名方式接入，避免虚构未实现的素材注册接口。

实际窗口再核对透明边缘、缩放清晰度、脸/脚的裁切、对话框与选项遮挡、差分切换，并覆盖本次承诺的窗口尺寸。静态合成图证明构图，真实场景才证明显示绑定与交互中的布局。
