# 准备创作基础

进入条件：已有用户确认的 [筹备方案](../plan-initialization/SKILL.md)。读取 [项目边界](../references/project-contract.md)，实际调用前补查扫描中仍未确认的相关环境项。

## 按缺口进入制作分支

保留完整已知清单，仅执行已确认的本次范围。按表加载适用子技能，已合格成果直接复用；同一材料同时存在多个缺口时，记录每项处理结果，不以文件存在概括为就绪。

| 触发情况 | 执行技能 | 交回基础准备的成果 |
| --- | --- | --- |
| 大原文、编码混杂、结构待整理或索引缺失 | [整理原文与有序分片](../prepare-source-text/SKILL.md) | 可读文本、有序分片、来源索引及完整性证据 |
| GUI 缺失、不合适或约定重做 | [GUI 设计与制作](../design-game-gui/SKILL.md) | 已确认方向、界面源码与素材、待运行核对项 |
| 音频用途未定、播放安排缺失或需准备音频 | [音乐与播放编排](../prepare-music/SKILL.md) | 已确定用途的曲目、使用表、必要派生音频与播放定义 |
| 要求立绘但缺图、透明度不合格或显示适配不足 | [角色立绘与显示适配](../prepare-character-sprites/SKILL.md) | 已确认角色基准、透明立绘、差分/布局映射及合成预览 |

已有文本、检索库或混合来源沿用原结构与引用方式。小而清晰的资料只需整理来源、设定、角色与索引，无需强制分片或新建数据库。

## 确认视觉基准

需要剧情插画时，先复用合适的基准或通过已配置 Image 能力准备基准样例，向用户展示角色外观、画风及参考关系，取得确认后再批量制作对应差分与素材。

已有明确确认且仍适用的基准直接继承。用户明确采用纯文字方案时，仅将不需要的剧情插画及其基准记为不适用，仍需 GUI 设计与确认；素材生成失败不自动改成纯文字或用占位图冒充完成。

## 准备 GUI

调用 [设计并制作游戏 GUI](../design-game-gui/SKILL.md)，判断已确认界面是否可复用；缺少合适 UI 时按该技能制作并展示候选，等待用户定向后落实界面代码和资产。

GUI 方向确认属于视觉基准确认。基础准备阶段交付界面源与素材，实际 GUI 核对由下一阶段完成开场整合后执行；未渲染的设计文件与未经确认的候选均不算已选定方向。

## 其他资产与共同交付

1. 依方案优先复用满足用途、角色、风格与技术条件的现有素材。导入时复制到项目管理区域，保留用户原件及来源说明。
2. 使用已启用的专业能力完成待制作项，明确各任务的输入、输出文件、用途和完成条件。同一文件保持单一写入责任人，交付后由 Coding 整合。
3. 图像、音频、字体等按已有能力和方案准备，不因列入清单就自动新增生成后端。素材名称表达用途，交付清单记录源/派生路径、用途、正式引用和处理依据。
4. 对每项分别记录原件状态、用途决定、派生处理、预览/试听和整合映射。各子技能拥有专属检查规则；基础阶段保留运行待验证项，技术参数一致不代替实际感知检查。
5. 失败或偏离基准的结果保留待处理，按现有配置的有界修复规则处理；外部任务结果不明先核对原任务，不盲目重复提交。

其他已纳入范围的资产按用途处理，不只做文件存在检查：

| 类型 | 缺口处理与交付 |
| --- | --- |
| 背景/CG | 映射场景与时段，检查画幅、焦点及 GUI 遮挡；不合适时按已确认方向等比适配、扩图或制作，预览最终构图，有意裁切先有依据 |
| 字体 | 检查正文/人名/标点实际字形、字重与加载效果；缺字时采用已确认字体组合或展示选项，交付字体文件和界面映射，长文本显示留待开场核对 |
| 语音/视频（仅适用时） | 记录台词/事件对应、顺序、音量及字幕/跳过要求；检查解码与代表片段，交付引用和播放控制，同步及跳过行为留待实际运行验证 |

素材已提供却没有用途的项目先补映射；用途已明确却没有合适素材的项目进入复用/处理/制作。原件、预览、正式资产和运行接入四者分开，避免原地破坏或以草稿充当成品。

## 结束条件

本次必需资料和基础素材已就绪，来源/用途及整合映射完整，适用的剧情视觉基准与 GUI 方向已确认，界面和播放/立绘定义已交付开场整合。资产阶段检查已执行，实际运行检查清单随交付移交下一阶段，不要求基础阶段先完成整个开场。可选和随剧情制作项明确保留在清单中。未满足的必需项如实保持待处理，只有用户调整范围后才从本次门槛移出；GUI 作为必要界面始终保留。

更新筹备文档中的实际成果与状态，进入 [制作可阅读起点](../build-opening/SKILL.md)。素材就绪不单独代表整个 init 完成。
