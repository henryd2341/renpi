# 准备音乐与播放编排

进入条件：音频已纳入确认的筹备范围；用途仍有歧义时先补澄清该项，不替用户默定。读取 [项目边界](../references/project-contract.md)。已有适用的音乐编排直接复用。

## 盘点与试听

1. 登记原文件及来源说明、格式/编码、时长、声道、可解码状态和已有用途记录；保持原件，转换结果另存派生文件。利用现有音频检查工具，不因技能需要就新增后端。
2. 有试听能力时检查代表段及首尾，辨别音乐、环境声、一次性音效、语音，记录可闻的情绪、速度感、突变、静音和失真。听感是候选判断，文件名不等于用途；无试听能力时保留听感待核对，向用户展示可播放素材或使用明确提供的说明。
3. 区分“文件存在”“解码通过”“内容适用”“播放编排确定”。未使用的曲目留在清单，不为消耗全部素材而强塞入开场。

完成标志：每份拟用音频都有可追溯文件、技术状态与内容依据；未知项显式保留。

## 确认用途策略

先检查用户是否已指定曲目用途或委托 Agent 编排。只有缺失时询问：这些音乐有固定安排，还是按已定故事与氛围由 Agent 配置？继承既有委托，不逐曲重复询问。

获得委托后提出有依据的编排：主菜单、日常、紧张场面、角色主题、关键事件、静默区间等只列适用项。同一曲目可复用，不将“一个角色一首歌”设为默认要求。涉及歌词、明显不符氛围或改变叙事重点的歧义，携试听片段或现有说明逐项澄清。

维护一份音乐使用表，优先并入已有资产清单；没有时可用 `authoring/handoff/audio-cues.md`：

| 字段 | 填写内容 |
| --- | --- |
| 资产与依据 | 稳定标识、源/派生路径、试听或用户说明、采用决定 |
| 叙事用途 | 场景/标签/事件与适用氛围，不确定处注明待决 |
| 生命周期 | 何时开始、保持、替换和停止；跨场景是否延续；没有音乐时的明确静默 |
| 播放配置 | 实际 channel 与 mixer、循环/单次、全曲或选定区段、淡入/淡出秒数、相对音量；具体值由内容与试听确定 |
| 检查状态 | 解码、试听、循环接缝、映射完成、待开场运行核对，分别记录 |

策略在需求/方案确认或已有委托内收口，无需新增每曲审批关卡；扩大素材制作范围则回到范围确认。

## 准备播放配置与派生素材

- 根据所用 SDK 的本地文档核对 API；缺少本地文档时查 [Ren’Py Audio](https://www.renpy.org/doc/html/audio.html)。`music` 默认循环、`sound` 默认单次，但最终配置显式表达意图。
- 普通 channel 同时播放一个文件；新 `play` 会替换旧音频。需要同时存在的 BGM、环境声和一次性音效分别安排通道。优先复用已有通道；确需新增时映射到适合的现有 mixer，保持偏好设置可控制，channel 名和 mixer 名分别记录。
- 明确 `play` 的 `fadeout` 作用于旧音频，`fadein` 作用于新音频；淡入淡出不等同于重叠交叉混音。按实际需要使用 `stop` 和 `if_changed`，避免同曲场景切换反复从头播。特殊 `audio` 通道适合叠加音频，但不支持停止/排队，需控制结束时机的长音频使用可控通道。
- 仅对已选音频做必要的格式转换、首尾处理、循环区段或音量调整，保留原件与参数。循环点通过实际试听检查接缝；不把整曲强行循环当作天然无缝，也不以波形峰值一致代替听感平衡。
- 需要新音乐但暂无适合文件时，列明用途、时长、是否循环与风格，使用已启用且实际支持的能力准备；缺少该能力则记录具体缺口，保留必需状态，等待用户提供或调整该项范围。

完成标志：必需音频可解码，使用表明确，必要派生文件及播放源代码已交付；待运行检查与已完成资产检查分开。

## 交回开场整合

交付文件、使用表和所需播放定义，供 [制作可阅读起点](../build-opening/SKILL.md) 整合。在实际单元核对触发/停止、跨场景延续或替换、循环接缝、重复进入、偏好设置音量/静音及适用的读档/回退行为；环境声与音效并存时检查互不误打断。

运行中的可闻结果才证明实际播放；日志、文件存在或静音录屏不代替试听。无运行音频证据时保留待核对，素材阶段交付不提前宣称运行通过。
