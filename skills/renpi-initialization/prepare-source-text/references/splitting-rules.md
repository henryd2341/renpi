# 文本边界与切分规则

仅在整理大文本时读取。本页是候选识别与完整性约定，不是通用于所有作品的章节语法。

## 候选正则

在规范化后的逐行文本上匹配，检测时临时去掉行末 LF，正文保持原样。以下为 Python `re` 语法，英文规则使用 `re.IGNORECASE`；按实际来源缩窄规则后再采用。

中文章/回/卷/部/节/幕：

```regex
^[ \t　]*第[零〇一二三四五六七八九十百千万两壹贰叁肆伍陆柒捌玖拾佰仟\d]+[章回卷部节幕](?:[ \t　:：、.．—-].*)?$
```

英文章/部：

```regex
^[ \t]*(?:chapter|part|book)[ \t]+(?:[0-9]+|[ivxlcdm]+)(?:[ \t:：.．—-].*)?$
```

前后附属部分：

```regex
^[ \t　]*(?:序章|序言|前言|楔子|尾声|后记|附录)(?:[ \t　:：、.．—-].*)?$
```

独占行分隔符：

```regex
^[ \t]*(?:\*{3,}|-{3,}|={3,}|(?:\*[ \t]+){2,}\*)[ \t]*$
```

这些规则有意保守：“第一章春雨”、`Chapter One`、特殊符号分隔线等先在未匹配样例中发现，再添加适合该作品的规则。数字编号、重复横线与匹配成功都只是候选证据。

采用规则前检查：

- 目录区是否出现同样的标题序列、点线页码或密集短行；目录正文保留，目录标题候选不等同于叙事章节边界。
- 标题是否嵌在引文、代码块、诗句或正文对话中；分隔符周围有无实际段落，避免空分片。
- 卷与章是否嵌套、编号是否重置、是否有上下篇；按出现顺序保留层级，不以提取出来的数字重新排序正文。
- 大文件扫描保留全局位置，可逐行流式处理；检查末尾和未匹配区域，不以只看前若干行代替全文件候选扫描。

## 范围与命名

边界用规范化全文 Unicode 字符偏移的半开区间 `[start, end)` 表达，并可另存便于阅读的行号。显式注明偏移单位；原始文件字节偏移另设字段，避免混用。

所有分片区间从 `0` 连续覆盖至全文长度，下一片 `start` 等于上一片 `end`。标题前的空行、章节之间的换行、分隔符及末尾换行均只归入一个区间；边界排序去重后跳过零长度区间。空文件记录为空来源，不伪造正文分片。

序号按原文顺序生成，例如 `000001-序言.txt`、`000002-第一章-01.txt`、`000003-第一章-02.txt`。序号/索引决定顺序，标题只是可读标签；路径保持在资料输出目录内。章内子片保留父章节引用。

## 无标题或章节过大

采用实际读取预算决定目标大小，优先从目标位置往前找到完整段落边界。保留段间原始空行；连同标题、换行计算分片大小，给后续提示与引用留余量。

超大单段转为句界候选时，识别引号配对与省略号等上下文；可靠边界不足则保留并登记超限项，另用按来源位置分段读取处理，实际验证覆盖完整后才接受为例外。切分是定位手段，不做删节、去重或摘要。

只有 `join(parts) == normalized_text`、索引区间连续且原件映射可回查，才算机械切分完整。内容提取质量、原作版本选择和剧情改编分别验收。
