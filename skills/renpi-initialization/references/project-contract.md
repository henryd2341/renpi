# init 使用的项目边界

这是 init 的项目边界；工作区读取与执行约束也供 Coding 共用。读取一次后按需回查，无需遍历历史议题或原型测试报告。

## 工作区读取与约束

新会话、恢复任务或切换项目时，先完成以下定位，再制作或委派：

1. 核对宿主给出的项目根目录、当前工作目录、可用工具和实际 shell。优先使用目录工具的 `path` 参数；使用 shell 时按实际 PowerShell 或 Bash 语法调用，Windows 本身不决定 shell 类型。
2. 列举目录后读取已确认的文件。`read` 用于文件；目录交给 `ls`/`find` 或等价目录能力。先读取适用的项目 `AGENTS.md`、宿主有效覆盖规则及已有交接，再沿真实索引定位本次来源与程序状态。首次 init 尚无这些文件时，记录缺项并继续扫描。
3. 列表截断时缩小到相关子目录或使用工具支持的完整列举方式；文件截断时按 `offset`/`limit` 续读。记录相关文件的已读、待读和缺失范围，任务依赖的依据覆盖完整后再下结论；无关依赖、缓存及历史产物按需跳过。
4. `EISDIR` 表示应改用目录列举；`ENOENT` 时回查已确认父目录、实际文件名及引用来源。核对后仍缺失就说明具体缺项，仅暂停依赖它的步骤；猜测路径、目录名或未读内容不充当事实，也不因读取失败把已有项目当作空项目。

### 用户约束与执行范围

- 继承已确认的项目长期要求和本轮明确要求，区分适用范围与有效期。仅本轮暂停的事项留在交接待办；用户确认要跨会话保持的要求按 [交接规则](../handoff-creation/SKILL.md#项目规则落盘) 写入项目 `AGENTS.md`。含糊或冲突的部分先澄清，保留无关既有决定。
- Image 停用时跳过该角色及新生图调用，仍可按已确认范围复用现有图片、字体和原生 GUI；Review 停用时跳过独立审查，Coding 的文件核对和候选验证分别按其执行范围处理。这些是用户选择，不是所有项目的默认设置。
- 区分只读文件核对、测试脚本、SDK 编译/lint、渲染预览、启动游戏和真实模型/素材调用。用户暂缓测试或运行时，先明确覆盖哪些动作；含糊的执行项保持暂缓，继续允许的编辑与只读核对。工具内部的执行同样受约束：`renpi_submit_candidate` 会编译/lint，若也在暂缓范围内，停在产物就绪并取得执行确认后再提交。
- 技能中的检查列表描述验收要求，不自动授予执行许可。暂缓项记为待验证，保留已有证据及其版本；用户确认基础流程通过不扩展成全量回归通过。`AGENTS.md` 是行为约束与导航，不是程序开关，跳过检查的文字不改变桥接提交策略。

### 验证工作区与资产引用

创建或复用 compile/lint、Review、预览、回归检查工程前，先按以下规则准备输入；正式安装、冻结交付与真实恢复备份不属于验证工作副本。

- **大文件为单文件 ≥ 1 MiB（1,048,576 字节）**。验证期间禁止复制大文件；图片、音频、视频、字体及资源归档无论大小均使用逐文件软链接引用已核对的原件。硬链接、目录 junction 和失败后改用复制均不符合此规则。
- `.rpy/.rpym/.py`、RPYC 等可写脚本/编译输入保持独立小文件；其中达到阈值的输入暂停验证，先拆分或安排独立可写方案。缓存、存档、persistent 及外部调用另行隔离，整个 `game/` 不作为链接目标。
- 软链接共享原件，不是只读屏障。确认检查只读取链接资产；源文件在本轮检查中冻结，记录目标及 SHA-256，执行前后核对链接身份与原件哈希。检查需要修改资产时，先暂停并说明所需写入，保留原件。
- 链接目标限本轮已核对的项目/SDK 普通文件，避免沿未知链接或重解析点取材；新建链接只位于分配的验证区。创建失败或权限缺失时报告具体路径和错误，保持待验证，不退回复制或自行更改系统权限。
- 同一串行任务优先复用一个活动工作区，Coding 与 Review 共享其有效证据。编译与冻结旧档/回退现场确需分开时分别登记用途；额外 before/after 工程只保留必要的小文件差异和链接，不再复制整套资产。
- 日志、命令/退出码、输入哈希、必要截图和复现步骤是长期证据；工作工程不是默认档案。检查成功且冻结产物/报告落盘、下游引用解除后回收本轮工作输入。仍被预览入口引用的工程标明保留理由；失败现场注明复现用途与清理时点，任务结束前处理，不无限增加轮次目录。
- 回收前确认任务已停止、绝对路径位于本任务验证区且没有待用引用；只删除自有副本或链接本身，保持链接目标、正式内容、冻结候选、历史兼容依据和用户存档。历史未登记目录先列清单确认，随后再清理。

完成依据：必要资产在验证区均为软链接，原件哈希未变，临时工程去向与证据位置可核对；单纯把目录加入 `.gitignore` 不代表回收磁盘空间。

## 职责与能力

- Coding 是统一对话入口与专业任务委派者。Writing 负责正文，Image 负责指定素材，Review 只读候选并交付报告；各角色只处理分配文件，交付完成后交接写入职责。
- 使用当前宿主实际提供的工具与已配置能力。本技能组组织工作，不提供桥接服务、模型后端、项目状态机或新编排引擎。缺失能力明确报告，不假设某个名字对应可调用 API。
- 工具按内建能力检查，无需用户重做工具选型。环境就绪检查仍执行；费用不是 init 的必问项或完成条件。
- 不自动安装或升级 SDK、模型、节点、工具，不自动启动或停止用户服务。需要额外环境操作时说明具体动作和影响，另行取得同意。

## 文件与状态

已有项目遵守自身已确认布局；下表是用途约定，并非每个路径都已存在。先核对目录，再使用适用路径：

| 区域 | init 使用方式 |
| --- | --- |
| `authoring/sources/` | 保存原资料、分片与来源索引，保留原文对应关系 |
| `authoring/shared/` | 共享脚本和基础素材的创作源 |
| `authoring/branches/<branch_uuid>/` | 对应分支专属资料、脚本与素材 |
| `authoring/handoff/` | 筹备方案、成果、决定、引用与待办 |
| 项目根 `AGENTS.md` | 已确认的跨会话约束和真实阅读入口；保留已有规则 |
| `renpi.json`、`renpi.local.json` | 读取已有项目与本机设置；机器路径留在本机层，身份字段由程序管理 |
| 程序状态、连接与恢复记录 | 公共桥接使用 `.renpi-live/bridge/state.json`；其他适配读取其实际存在的状态路径，通过现有操作入口推进 |
| `game/` | 最后成功接入的运行内容，使用程序的新建/适配或验证接入路径更新 |

筹备文档可以先建立，但文档存在不代表项目已经初始化或适配成功。保留原项目身份、用户素材、运行内容、存档与 persistent；覆盖既有成果前说明影响并确认，按既有保护机制保留原件。

素材加工在创作区生成派生文件，原件保持可回查；清单记录来源、用途、必要处理与正式引用。沿用项目已有索引/清单，技能中的文件名只是缺少现有布局时的默认值，不另建一套平行业务状态。

## 内容与成功边界

- 原文改编与自由创作分开处理，已确认依据优先。未知未来剧情不要求穷举，资料分片不等于制作完整游戏。
- 产物交付、技术验证、视觉检查、Review、运行接入与用户确认是不同结果；分别记录实际完成状态。
- 当前方案内必需成果失败时保留并诊断，修复使用现有有界额度。未知外部执行结果先核对原任务；保留在途写入归属，避免重复派发或同时修改同一文件。
- 范围变化回到用户方案确认；素材缺失不自动降级模式，状态异常不自动重建项目。纯文字模式可免除其不需要的剧情插画，GUI 仍为必需成果，其设计、确认和实际可用性保持完整。
