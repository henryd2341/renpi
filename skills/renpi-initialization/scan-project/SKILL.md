# 扫描项目与环境

进入条件：目标项目目录已经明确。先读取 [项目边界](../references/project-contract.md)，按其中的 [工作区读取与约束](../references/project-contract.md#工作区读取与约束) 核对目录、工具和实际 shell，再扫描材料；此阶段以只读检查为主。

## 先扫描项目文件

1. 读取有效项目规则、项目说明、已有 init 记录、声明与适配信息，区分新建材料目录、已适配项目、准备中项目和异常残留。已有项目保留原身份；异常残留先报告，避免按空项目重建。
2. 查找原文、设定、角色资料、参考图、正式素材、脚本、界面和项目配置。沿已有索引读取相关内容，列明来源与用途；跳过无关依赖、缓存和历史测试产物。大型资料记录已读范围和待读范围，不以抽样代替全篇整理。
3. 继承用户已明确指定的依据。用途不明、多个版本或相互冲突时，列出具体文件和冲突位置供下一阶段询问；文件修改时间与文件名不足以决定权威或正式采用。
4. 整理可复用、待判断、已知缺少的材料，保留原始文件。扫描发现的参考图片与正式游戏资产分开标识。
5. GUI 单独检查已有界面代码、页面与控件状态、UI 素材、字体及方向确认记录。没有合适 UI 时记为待设计/制作，即使纯文字项目也保留此项；具体制作交给 [GUI 技能](../design-game-gui/SKILL.md)。

材料检查进一步记录下表事实；此处诊断缺口，整理和制作留到方案确认后：

| 材料 | 扫描内容与分流 |
| --- | --- |
| 原始文本 | 文件类型、大小、编码/换行迹象、已有索引、常见标题或分隔符、提取与 OCR 情况、已读覆盖；单一大文件或结构混乱进入 [文本整理](../prepare-source-text/SKILL.md) |
| 音频 | 文件清单、实际格式/时长与解码检查情况、用户说明、场景用途及已有播放定义；只有文件而无使用安排记为待编排，进入 [音乐准备](../prepare-music/SKILL.md) |
| 角色立绘 | 角色/服装/表情覆盖、真实透明度是否检查、画布与人物区域、游戏画幅与 GUI 遮挡、差分对齐；缺图、去背或显示适配进入 [立绘准备](../prepare-character-sprites/SKILL.md) |
| 其他资产 | 背景/CG 的画幅与焦点、字体的字形覆盖和加载情况，以及方案确有需要的语音/视频等；分别标明“有文件”“用途明确”“技术可用”“已预览/试听”，未检查项保持未知 |

## 再检查环境

1. 检查当前宿主提供的内建工具、已加载的 Agent/SKILL 与项目设置；这些是待核查事实，不是要求用户重新选型的问卷。
2. SDK 依次查显式指定位置、本机配置、`RENPY_HOME`。记录实际选中的位置和版本，用轻量本地检查确认入口可用；使用 SDK 自带 Python，无需另列独立 Python 安装条件。
3. 检查当前 Pi/Coding 入口、已配置的专业能力，以及项目创建、适配、验证和接入能力是否实际存在。以当前安装与能力声明为依据，不假定历史原型已成为可用接口。
4. 对已明确要使用的素材后端检查其配置与依赖。选择 ComfyUI 时核对 `comfy` CLI、已配置服务和工作流；纯文字或只复用现成素材不要求该后端。尚未确定用途的能力标为待确认用途后检查。
5. 环境检查不调用模型或生成素材，不自动安装、升级、启动或停止服务。凭据只检查所需配置是否存在，报告排除其值。发现缺项说明影响及最小处理动作，后续仅阻塞依赖它的步骤。
6. 检查当前可用的 SVG 渲染/图片展示能力和实际字体。区分“能编辑设计文件”“能渲染并展示候选”“能运行游戏界面”，三者分别记录，不把模型生图后端作为矢量 GUI 草图的必需前提。
7. 按材料缺口核对文本提取/编码处理、图像 alpha 检查/编辑/去背、音频解码/试听能力；只检查适用项的可用状态，不在扫描中转码、分片或处理资产。元数据读取、内容感知和真实运行能力分开记录。

## 交付与结束

交付扫描摘要：项目识别结果、依据与材料清单、冲突及缺项、环境检查结果、尚未检查的范围。区分“已检查可用”“缺失或异常”“未检查/当前不需要”，不把后两类写成已通过。

文件和环境两部分都已核查或明确记录缺口后，进入 [逐项澄清需求](../clarify-requirements/SKILL.md)。需求明确后出现新的条件依赖，只补查相关环境项。
