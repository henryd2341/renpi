# 审查报告内容模板

使用现有工具字段和分配路径；下面的标题是文稿结构，不是新的运行协议。没有程序提供的信息写“待核对”，不编造身份、版本、哈希或工具回执。

```markdown
# 本轮 Review

## 目标与结论
- 委派任务/目标分支/位置引用：
- 当前候选及要求版本引用：
- 用途：候选接入审查 / 明确分配的局部咨询
- 总体判定：通过 / 需修改 / 受阻（三选一；局部咨询写总体未评估）
- 一句话理由：
- 对应报告/证据位置：

## 输入与覆盖
- 已读来源、实际文件、变更基线、视觉/演出约定：
- 实际 SDK/关键配置与构建依据：
- 本轮检查范围、未受影响范围及其复用依据：

| 要求/检查 | 当前产物及位置 | 证据引用 | 结果 | 说明 |
| --- | --- | --- | --- | --- |
| 例：音频退场 | 场尾 stop 与声音文件 | 当前版本运行记录 | 通过/失败/未执行/过期/不适用 | 实际观察；不适用需理由 |

## 确定问题
### R-01：具体问题
- 类型与影响：阻止接入的问题；影响什么实际行为/明确要求。
- 位置：当前文件/行或场景区域；内容问题附源位置。
- 依据、期望与实际：
- 证据/复现：
- 最小修复目标及建议责任：交 Coding 统一安排。
- 复验条件：怎样观察到此问题确已消失。

## 受阻项
- 缺失的材料/设施/身份依据，妨碍哪项必需判断，Coding 最小补充动作。

## 可选建议
- 有价值但不阻止接入的改进；无则写无。

## 复审对照（首次审查省略）
| 原问题 | 当前证据 | 已解决/未解决/被替代及依据 | 连带检查 |
| --- | --- | --- | --- |

## 交接与边界
- Coding 下一步、仍待其受控接入后确认的项目：
- 未执行事项及原因、报告适用范围：
- 当前报告不代表已接入；候选/要求变化后重新核对适用性。
```

交付前删掉示例行与空标题内的说明，保留必要的“无 / 不适用及原因”。确定问题为零时直说，不为凑数量创造问题。正文能简短说明就不另附长篇分析轨迹。

## 判定校准

| 事实 | 合理报告 |
| --- | --- |
| 全部必需条件与当前证据齐全，只想把淡入从 0.4 秒换成 0.6 秒 | 通过；淡入偏好为可选建议 |
| 当前编译定位到本候选未闭合字符串，运行因此未开始 | 需修改；给源位置与诊断；运行项注明依赖该问题，修复后补验 |
| 音频相关改动只有 play 日志，没有匹配的试听证据且本轮缺试听设施 | 受阻；明确音频生命周期待核对，声音是否错误仍待实际观察 |
| 已确认一处原文遗漏，同时当前版本必需旧档证据独立缺失 | 受阻；遗漏列确定问题，旧档列证据缺口，两者分别处理 |
| 旧候选报告通过，但图片或脚本在报告后已替换 | 旧报告过期；当前审查受阻，补齐当前证据并检查受影响部分 |
| 只让 Review 看一张 CG，未分配其余候选检查 | 交局部意见，总体未评估；不提交候选通过结论 |

“已接受的限制”只说明它是否在本轮范围外，不自动豁免已确认的必需要求。实际要求有冲突时由 Coding 取得明确决定，Review 保留冲突与影响。
