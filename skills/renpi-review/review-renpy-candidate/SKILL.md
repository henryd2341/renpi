# 审查 Ren’Py 候选

判断这份候选是否满足本轮已确认要求，给 Coding 可定位、可验证的结论。Review 只读产品，写审查报告；修复、跨角色委派和实际接入由 Coding 负责。

先读 [Review 边界与判定](../references/review-contract.md)，按本轮目标加载以下步骤。以实际文件和证据为准，不以作者摘要或工具“成功”消息代替审查。

| 顺序 | 技能 | 完成条件 |
| --- | --- | --- |
| 1 | [确认审查依据](../read-review-context/SKILL.md) | 目标/版本、要求、变更范围、来源和文件权限明确；检查范围可解释 |
| 2 | [检查正文与连续性](../review-story-content/SKILL.md) | 原文/细纲、有效前情、玩家权限与文本记忆核对完成；内容问题有依据 |
| 3 | [检查脚本与演出整合](../review-renpy-integration/SKILL.md) | 调用、符号、素材/音频/ATL/界面和兼容影响核对完成 |
| 4 | [核对验证证据](../verify-review-evidence/SKILL.md) | 必需检查的版本、结果及观察范围清楚；证据缺口与实际缺陷分开 |
| 5 | [出具报告与复审](../report-review-result/SKILL.md) | 单一结论、覆盖范围、问题/建议和复验目标明确，交回 Coding |

## 按变更收敛工作

- **新单元/开场**：核对本轮全部正文、调用边界及必需素材，结合已确认 GUI、音乐和立绘映射检查实际演出。
- **原文改编**：对照采用源范围，不套自由创作文风评分；分页和角色归属应保留原文含义。
- **局部修订**：读取改动、调用方及受影响上下文。纯音乐/表情调整不重审全篇文学风格；插句或改变调用链仍要重新判断兼容和运行范围。
- **复审**：核对新候选、原问题和修复影响；关闭已解决问题，补查连带回归，不为开启新轮次增加主观要求。

局部修订仍可接受完整候选的接入审查；如果 Coding 只委派“看一张图/一段文字”的局部咨询，报告只给该面意见，候选总体门槛留给完整审查，不把局部满意写成候选通过。

## 收口

交付分配位置的报告及必要证据引用。已确认缺陷说明“哪里、违反什么、产生什么影响、怎样验收修复”；缺证据说明具体缺项；纯优化单列。完成本轮规定范围后停止，由 Coding 统筹后续，不自动扩成全仓审计或递归专家会审。
