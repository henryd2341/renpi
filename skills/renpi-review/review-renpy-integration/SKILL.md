# 检查 RPY 与演出整合

以实际 [Coding 整合产物](../../renpi-coding/implement-renpy-scene/SKILL.md) 为对象。未知语义复用 [SDK HTML 检索](../../renpi-coding/consult-renpy-sdk/SKILL.md) 查当前版本，只读相关章节，不再建另一套文档检索器。

## RPY 调用与状态

- 入口 label 存在，参数/调用方对应；call/return 与 jump 的用途正确，有稳定接续路径，不意外落入下一个 label 或空栈返回主菜单。选项结果与本轮意图及既有 Ren’Pi 入口一致。
- Character、label、image tag/属性、transform、screen、store 变量、通道和文本映射在全部相关加载脚本中共存；目录不是命名空间，共享修改追查引用方。动态引用沿实际分支检查，lint 没报错不自动证明覆盖。
- 正文常量与稳定语句映射、新增角色及转义保持语义。可变剧情状态与 init 常量分开，保存/回退所需数据可追溯；外部任务身份仍由程序管理。
- screen 预测/重算和 init 的实际副作用受控，渲染不重复提交选择、写任务或派发制作。调用已有业务动作的身份与幂等边界，不以 UI 按钮存在作为业务正确证明。

## 图片、音频与界面

只检查本轮存在或受影响的媒体。读取 [演出检查表](../references/presentation-checks.md)，对照真实文件、素材交付映射和当前场景证据。

先核对本轮演出基线、明确例外及公共实现的调用范围，再按 [动态验收场景](../references/presentation-checks.md#动态验收场景) 对应当前证据。区分“缺少约定效果”“已实现但状态错误”“只有静态证据”与“用户已选不同风格”；仅最后一种且实现符合约定时保留原选择。说话焦点、入退场、渐显和恢复分别给结论，避免用一个泛化的动画通过覆盖全部项目。

图像应实际查看像素，不只看生成提示/文件名；音频结果区分文件/命令存在与真实试听；动画区别静态截图与时序观察。已有匹配候选的可信观察证据可引用，查清覆盖范围再决定是否补看，不为所有图片重新生图或重复重放。

确认缺陷在哪一层：原图错误、Coding 映射/布局错误、音频用途缺失、生命周期错误或检查证据缺失。报告具体责任建议给 Coding，不自己切换 Image 后端、重绘或改脚本。

## 修订与旧档

涉及已有内容时核对 [Coding 兼容策略](../../renpi-coding/references/coding-contract.md#正文修订与兼容) 和 [Q85 确认](../../../docs/wayfinder/tickets/RP-011.md#q85-confirmed)：同路径上一已接入 RPYC、稳定执行语句及本轮实际结构变化分别检查。

单句正文修订的历史结论不自动覆盖插删、重排、说话者/调用栈变化或多句多角色。核对实际旧档落点、新正文、原生回退与当前绑定的证据；来源不明或只给旧报告时记录证据缺口。已复现落点错误则是缺陷；恢复入口由既有流程和用户决定，Review 不猜跳转点。

## 完成条件

整合检查覆盖本轮实际受影响路径，每个问题有文件/位置、依据和可观察结果。静态判定、图像观察、音频试听、动画交互及存档结果分开，交 [证据核对](../verify-review-evidence/SKILL.md) 后统一报告。
