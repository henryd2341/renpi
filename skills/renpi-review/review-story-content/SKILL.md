# 检查正文与连续性

依据已确认 [审查范围](../read-review-context/SKILL.md) 和 [Writing 契约](../../renpi-writing-plots/references/writing-contract.md)。Coding 的技术整合可能改变显示语义，检查实际候选正文，不只检查 Writing 的原始交稿。

## 按正文来源检查

- **已有原文**：对照采用的源范围逐段确认遗漏、重复、顺序、说话者、信息和关键措辞。将叙述归入 Character、自然分页、技术转义与故事增删分开判断；依据角色归属和实际显示语义评估，不以字节完全相同作为唯一标准。原文未明确部分保持其原有歧义，不替作者补结论。
- **自由创作**：对照本轮修订细纲、有效前情和实际采用的文风档，检查因果、角色动机、声音、视角知情范围、节奏与停止点。未采用的风格占位规则只作参考；不把所有文稿改成审查者偏爱的写法。
- **混合或缺段**：确认改编/续写边界及明确许可；资料缺失与允许原创是两回事。候选把缺失材料擅自补成既定事实时给出具体位置与依据。

## 所有路线的共同检查

1. 本轮开头接得上上一有效单元尾部；时间、地点、在场人物、伤势/服装/物件和称呼连续。人物说法、猜测与客观事实分开，尚未得知的信息保持未知。
2. 当前玩家输入可忠实呈现；新增玩家台词、行为和内心分别对照既有权限。主语为玩家不自动意味着越界，已确认动作也不自动允许增添情感结论。未选项及后果保持候选，原文改编中的既定角色台词按源文和项目约定处理。
3. 选项文案、剧情结果及 RPY 控制流含义一致；本轮停在约定输入点/源文自然边界，而非替玩家选定下一步或无限续写。
4. 字面方括号、花括号、反斜杠、标点、插值和分句处理保留预期显示；文本常量与实际说话者/语句映射对应，避免整合后错句、重句或插值泄露。
5. 图像、背景人物、音乐或字幕可能提前透露身份/事件，结合当前视角核对；“文字没说”不等于演出没有越过剧透边界。

## 文本记忆与问题记录

核对 `story-text-notes.md` 或现有同类记录是否来自**当前实际正文**；候选/已采用状态、来源、角色认知、已发生事件和未定事项相互一致。修订后的记忆不提前替换有效前情；工程参数/故障归工程交接，不混入故事事实。

每个内容问题给出源位置、候选位置、差异、影响和修复目标。需要重写时交回 Coding 安排 Writing；Review 提供定位和必要的短说明，不另写整篇替稿。没有具体契约依据的“更有感染力/更像某文风”单列可选建议；必需依据缺失交 [证据检查](../verify-review-evidence/SKILL.md) 处理。
