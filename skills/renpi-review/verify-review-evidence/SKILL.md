# 核对验证证据

读取 [判定规则](../references/review-contract.md#判定规则) 与 Coding 的 [候选验证](../../renpi-coding/verify-renpy-candidate/SKILL.md)。优先审阅已有实际证据，而非无条件再运行一整套。

## 对每项必要检查问清四件事

1. **测的是哪份**：程序候选引用、源码/构建/素材依据、实际 SDK 和关键配置是否对应当前候选。哈希由工具或程序生成并核对，模型手写字符串不作身份证明；文档名字相同也不证明内容相同。
2. **实际做了什么**：命令/退出码/完整诊断、截图/运行记录、复现入口和观察步骤。检查者是否真的读取输出；成功退出、日志存在和“所有测试通过”的文字分别核对。
3. **证明了什么**：编译/lint 证明的静态范围；素材技术检查、真实显示、试听、动画操作、旧档落点各自的观察范围。动态路径和隐藏依赖可能超出静态检查。
4. **还缺什么**：必需失败、未执行、过期、依赖阻断与不适用分别记录。不适用应有理由，例如“本轮无音频且未改音频引用”，而非空白即默认通过。

每份候选保留 Coding 契约要求的编译、lint、产物/引用/入口证据；附加运行项由真实改动决定。纯措辞调整不要求重播全篇；涉及素材/流程/交互/保存的修改按其受影响路径判断。

## 必要时补一个最小检查

只读定位即可解答的先读源码、源文或当前 SDK。仍需复现时，按 [验证工作区与资产引用](../../renpi-initialization/references/project-contract.md#验证工作区与资产引用) 复用已分配的完整工程：大文件与媒体资产只用软链接，独立保存/持久化区域与外部调用继续隔离；复用现成检查入口和命令，不另建通用测试平台。补查完成后释放工作区引用，由所属任务回收。

SDK compile/lint 会经历加载/init、生成 RPYC 或缓存，编译还可能清理孤立 RPYC。先确认检查副本和副作用隔离，再执行；保留冻结候选、上一已接入 RPYC 和历史存档原件。报告记录执行前后实际版本及输出，避免验证动作破坏被验证依据。

真实运行与用户阅读分开，检查不提交真实选择、不派发真实制作，也不污染真实存档。需要唯一创作 GUI 时将明确步骤交给 Coding 在受控衔接阶段安排，不争用窗口。缺设施时保留待验证项，不用模拟成功替代观察。

## 区分结果

- 编译诊断定位到本候选的错误、已复现错图/错曲/控制流/旧档落点：确定缺陷；列位置、重现路径与诊断。
- SDK 缺失、检查工具超时、视听设施缺失、候选/证据版本不匹配：证据或设施缺口；记录具体妨碍的判断。
- 已确认错误导致下游运行没开始：下游标为“未执行，依赖问题 R-xx”，不伪造结果，也不掩盖先修已知错误的顺序。
- SDK/lint 的建议或警告按实际内容判断：触及要求/正确性则跟进，纯优化保持可选；零退出码不覆盖报告中的实质问题。

结束前再次核对候选与要求版本。中途变化的旧结果只适用于其原输入，交 Coding 重新安排受影响检查与审查；已有明确发现保留，不悄悄切换到新目标。进入 [报告](../report-review-result/SKILL.md)。
