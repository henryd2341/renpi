# 长剧情的分轮委派

当本轮资料多、剧情跨度大或需要独立内容复核时，由 Coding 读取本页安排；短单元可在一次 Writing 调用中依次完成，不因阶段多就强制创建多个 Agent。

首版采用多次、分阶段任务，沿用 Coding 作为专业任务委派者的约定。Writing 返回阶段成果与协作需求，Coding 在宿主实际提供的能力内调用或继续对应任务；调用接口与递归深度不由技能虚构，也不新增常驻调度器。

## 有用的拆分

| 轮次 | 输入 | 交付及接续 |
| --- | --- | --- |
| 依据与粗纲 | 本轮要求、来源索引、目标前情 | 上下文底稿和粗纲；原文路线只交读取依据与源范围，跳过纲 |
| 风格与细纲 | 自由创作粗纲、已有文风档、指定修改点 | 使用的文风档和细纲；原文路线整个跳过 |
| 正文 | 原文范围，或细纲/文风；Coding 模板 | 基础 RPY 与整合说明，单一 Writing 写入者 |
| 必要的独立内容复核 | 正文、关键依据、约束、需核对的问题 | 只读意见与具体位置；Writing 集中修订后生成/更新文本记忆 |

原文长篇优先按自然单元分轮，避免一轮“概括全部后再凭摘要改编”。自由创作的资料检索和只读意见可独立并行；具有因果承接的细纲与正文按前置结果顺序执行。最终正文整合和记忆由明确责任人完成，避免多个 Agent 各写各的连续剧情。

## 每轮交接最小内容

交接目标及停止点、目标路线/位置的既有引用、实际输入路径和已读范围、仍适用的用户决定、唯一输出范围、完成条件，以及上一轮成果和本轮具体改动问题。只传相关材料；摘要带源引用，重要台词和争议事实回查正文。

若使用新上下文，把当前选定方案与弃用候选分开；若继续同一 Agent，也重新指出本轮修订范围。子任务只回交成果/证据/阻塞与推荐下一步，由 Coding 安排后续调用，避免依靠子任务自行递归续派。

## 停止与返修

优先集中收集一次内容意见，再按任务已有修订额度处理；没有指定额度时先做一轮有针对性的复核与修订，仍有实质分歧就交回 Coding 决策，而非无限互评。纯偏好建议不自动触发重写，也不将模型之间的一致赞同当作用户认可。

工具暂不支持多次/独立调用时，由当前 Writing 按相同阶段顺序产出，并明确缺少独立复核；仍可交付正文初稿，不伪称已经由另一 Agent 审过。
