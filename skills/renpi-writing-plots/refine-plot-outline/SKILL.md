# 修订细剧情大纲

进入条件：自由创作的 [粗纲](../draft-plot-outline/SKILL.md) 与 [文风档](../apply-writing-style/SKILL.md) 已可用。有原文改编的范围跳过本阶段。

## 修订而非抄长粗纲

结合已读前情重新检查粗纲，修正跳跃的动机、无依据的新设定、重复桥段和过早揭示的信息。风格只影响呈现，文风调整不自动推翻已经明确的剧情要求。

按场景展开足够支持正文的细节：

- 时间/地点、出场人物、采用视角，以及开场时各人知道什么。
- 场景目标、实际行动与关键对话意图；对话说出什么、隐瞒什么、如何改变关系或推进事件。
- 信息揭示次序、必要的感官/动作细节、节奏快慢与转场依据。对话比例按场景功能安排，不用无效聊天凑数。
- 场景结束时发生的变化、伏笔的埋设/回应、下一场承接点；未揭晓的真相与角色误认保持区分。
- 到达玩家决定处的停止方式、候选选项的文字意图，或已明确允许代写的范围。

不将细纲写成全文，也不强制每场填满表格。对粗纲发生的重要调整简述原因；人物目标或用户选择改变等越界事项交回 Coding，普通连贯性修正直接处理。

## 收口

用一次集中检查回答：事件是否接得上、人物是否凭空知情、玩家是否被替做决定、本轮是否有实际变化、下一轮从何处接续。需要独立意见时由 Coding 按 [分轮委派](../references/staged-delegation.md) 安排，沿用本轮修订额度，避免反复造纲。

完成标准：正文可以据此直接展开，关键因果与角色声音有依据，结束边界明确。保存修订细纲及粗纲变化说明，交给 [基础 RPY](../write-renpy-script/SKILL.md)；提案仍是提案，实际发生事实以后续采用正文为准。
