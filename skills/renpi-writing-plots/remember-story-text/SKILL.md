# 记录下一轮值得知道的文本

进入条件：本轮基础正文已完成内容修订。记录的是项目故事文本，不是资产元数据、日志或宿主个人记忆。先读 [Writing 边界](../references/writing-contract.md)。

## 从最终交付稿提取，不从大纲推测

重读本轮正文与已有适用记录，只写会影响续写的一次性增量及必要的当前状态：

| 值得记录 | 记录方式 |
| --- | --- |
| 实际事件与位置 | 谁做了什么、时间/地点如何改变；引用正文场景、台词或源文位置 |
| 人物知情与关系 | 谁已知道/仍误解什么，承诺、冲突或关系变化；事实、人物认知、读者可知分开 |
| 会持续的文本细节 | 物件去向、伤势、称呼约定、规则及身份线索；只收本轮文本明确出现或已有依据支撑者 |
| 伏笔与未解问题 | 已埋、已回应、仍悬而未决，并指向文本；作者打算以后写的方案另标计划 |
| 接续点 | 最后场景/动作/关键台词、已选输入及下一次等待什么；关键原话短引保真 |
| 来源与修订 | 使用了哪段原文/前情；本轮替换了哪些旧记录，哪些结论待采用后才生效 |

视觉、音频或环境引发的事实若正文已明确表达，可记录其故事含义；不抄图片尺寸、音乐路径、工具任务 ID 或播放日志。风格偏好留在文风档，仅引用适用版本。角色定义合并、标签出口和 SDK 检查等工程事项放在给 Coding 的交付说明里，与故事文本记忆分开。

## 记录形态与状态

沿用项目已有文本记录，没有时使用本轮分配目录里的 `story-text-notes.md`，包含：适用路线与位置引用、对应正文文件/修订、采用状态、上述必要增量、接续点、来源与未决事项。可以用短标题和条目，不为每句文本造对象或要求数据库。

- 默认标为本轮候选记录。下轮收到 Coding 的实际采用结果后，才把相应文本变化纳入有效前情；取消、未选或旧版本候选仍作为候选保留。
- 分支专属变化留在本分支范围，不写进全局设定；祖先资料按 flow 引用，不复制整棵故事树。仅在明确要求修改全局依据时提交对应建议给 Coding。
- 修订已有正文时列出应替换/作废的旧结论及新依据，保留历史引用；在采用前不覆写有效摘要。即便正文只改措辞，也核对记忆中的原话和定位是否需要更新。
- 人物说谎、猜测、梦境和未选未来保持性质标记，避免下轮把它们当客观已发生事件。

## 自检与交回

逐条确认记录能在当前依据或正文中找到支持，未把计划写成事实；检查会影响下一轮的关键变化没有漏记。内容变长时压缩重复描述，保留有效状态与必要引用，不用字数上限截掉关键承诺或线索。

若本轮没有值得新增的事实，明确写“本轮无新增需持续记录的文本事实”，仍保留正文引用与接续位置。摘要用于定位，回查正文仍是解决歧义的方式。

完成标准：下一轮能据此定位有效前情与源文本、接上本轮结尾，并辨明候选/计划/事实。连同基础 RPY 一起交回 Coding，写入记录本身不代表候选已采用。
