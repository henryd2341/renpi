# 创作本轮剧情

这是 Writing 的导航入口，适用于 init 首个单元、后续创作及指定正文修订。交付重心是好读、连贯、符合依据的剧情与可继续使用的文本记录，不是独立可运行的完整游戏。

先读取 [Writing 边界](../references/writing-contract.md)，核对 Coding 提供的任务、目标路线与位置、输入和输出范围。继续已有工作时复用仍有效的成果，仅重做受新要求影响的部分。

## 先读取，再分路

第一步始终执行 [读取已知文本](../read-plot-context/SKILL.md)。根据本轮实际采用的模式和来源，沿下表按需加载下一项，不一开始读完整套文风资料。

| 本轮情况 | 执行路线 |
| --- | --- |
| 有明确原文，当前单元按原文改编 | 读取已知文本 → [基础 RPY](../write-renpy-script/SKILL.md) → [文本记忆](../remember-story-text/SKILL.md)；跳过粗纲、通用文风和修订细纲 |
| 自由创作，只有设定/人物/前情或用户行动 | 读取已知文本 → [粗略大纲](../draft-plot-outline/SKILL.md) → [文风占位指导](../apply-writing-style/SKILL.md) → [修订细纲](../refine-plot-outline/SKILL.md) → 基础 RPY → 文本记忆 |
| 原文改编与续写均已明确纳入本轮 | 分清对应范围：原文段走改编路线，新增段走自由创作路线；记录接缝与各自依据 |
| 只修订已有正文 | 先核对修订范围及原依据；措辞修订不强制重做大纲，情节变化才更新受影响的纲和记忆；最终仍交基础 RPY 与文本记录 |

“有原文”指本轮有采用的实际剧情文本；世界观设定、梗概、角色卡或另一条路线的正文不自动成为当前改编原文。源文缺段、模式不明或到达未授权续写的末尾时，将具体缺口交回 Coding，不静默切换模式。

## 分阶段执行

- 普通短单元由一次 Writing 任务依次执行；篇幅长、依据多或需要独立复核时，Coding 使用 [分轮委派](../references/staged-delegation.md)。阶段之间传文件及具体问题，不要求每轮重读全部会话。
- Writing 把方向冲突与必要协作需求交回 Coding；已有委托范围内的写作细节自行完成，不给每份纲增设用户审批门槛。
- 原文路线仍检查忠实度、可读性和玩家边界，但不套通用风格模板改写原作。自由创作的文风档是本轮约束，不取代人物动机、因果和场景目标。
- 本轮到达约定的自然停止位置或下一玩家输入点即停止正文。未选行动、未来结果及备选构思继续保持未发生。

## 交付

返回基础 RPY 路径、适用的纲/文风引用、文本记忆路径、采用来源范围和停止位置，并列出需 Coding 处理的接入说明或未决项。

完成标准：本轮正文已写实，依据与连续性核对过，下一轮所需文本变化已记录；“Writing 已交付”与“候选已采用、游戏可运行”分别表达。后两者由 Coding 的真实整合结果确认。
