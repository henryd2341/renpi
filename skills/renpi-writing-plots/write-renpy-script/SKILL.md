# 写基础 Ren’Py 正文

进入条件：已读取本轮依据。原文路线有明确原文范围；自由创作路线有 [修订细纲](../refine-plot-outline/SKILL.md) 与本轮文风档。遵循 [Writing 边界](../references/writing-contract.md)，正文优先，语法只学当下需要的部分。

## 先按依据完成剧情

**原文路线**：按源文顺序保留事实、叙事视角、人物声音和关键措辞，完成适合视觉小说阅读的叙述/对话分配及自然分页。缺说话者时回查上下文；仍不确定就标明具体位置。通用文风、对话占比与占位禁词表均不加载，不为“游戏化”补剧情、制造选择或把原文角色台词删除。用户明确要求的改动单独标明；若与既有玩家控制约定冲突，交回 Coding 明确取舍。

**自由创作路线**：依细纲写实际场景而非纲的扩写说明。让行动、台词和信息揭示构成推进，人物说话有各自目的与表达习惯；按文风档自检视角、节奏和玩家边界。正文发现更自然的小调整可直接处理并回写受影响细纲，改变方向的调整交回 Coding。

两条路线都在本轮约定边界停下。当前玩家输入可以忠实呈现；未选台词、动作、情感结论与后果不自动成为正文。交互点的选项意图交给 Coding，除非模板已明确分配具体结构，否则不擅自编排菜单跳转。

## 只写必要的脚本层

1. 优先使用 Coding 给定的基础 RPY 模板、入口和角色标识。旁白与人物对话保持简单；新登场角色可随文提供 `define <标识> = Character("名字")`，列出新增定义，Coding 负责共存检查与整合。
2. 模板不完整时先完成能明确归属的剧情文本与基础语句，将缺失的入口/角色映射交接给 Coding。保持产物位置在分配目录，不为了让单文件运行而创建新游戏工程。
3. 检查明显的引号、缩进和段落问题，指出涉及引号、反斜杠、方括号插值或花括号文本标签的字面内容；技术转义处理应保留实际显示语义。复杂 Python、界面、ATL、存档兼容、素材调用与流程控制留给 Coding。
4. 音乐、立绘动作、场景效果等仅在有依据且有助呈现时作为简短创作提示，引用已有素材标识或说明需求。资源尚无定义时写在交接说明中，不伪造可执行调用；素材缺口不应占据正文写作主体。

## 语法按需查 SDK

优先查当前任务选定 SDK 的 `$RENPY_HOME/docs`，实际安装使用 `doc/` 时读取该目录；SDK 位置继承 Coding 已核对的路径，不写入共享文稿。只检索当前需要的 say、Character、label、text/interpolation 等章节，不复制整套教程进技能。

本机参考安装的文档位于 `doc/`，但技能不绑定这台机器。文档暂缺时保留剧情与最基础表达，注明待 Coding 核对的语法点，避免将整轮工作变成环境修复。

## 交付前只读一遍实际正文

- 原文路线对照本轮源范围，核对遗漏、重复、说话者与故事改动；自由创作路线核对人物动机、场景变化、视角知情边界与约定文风。
- 检查上一轮尾段接本轮开头是否连贯、本轮末尾是否停在约定位置；删除空泛总结、重复交代等无用文字时仍遵循原文忠实边界。
- 将真正需要修正的正文修正后，再做 [文本记忆](../remember-story-text/SKILL.md)，避免记忆来自旧稿。

交付独立基础 RPY、来源范围或细纲引用、新角色定义与必要整合说明，明确尚待技术核对处。编译和游戏运行是 Coding 后续证据，不把 Writing 的内容检查说成接入成功。
